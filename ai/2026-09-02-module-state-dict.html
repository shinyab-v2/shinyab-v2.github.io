AI 전문 개발 학습 #03 — nn.Module 등록 구조와 state_dict 해부

nn.Module의 submodule·parameter·buffer 등록 원리, ModuleList와 일반 list의 차이, state_dict key·checkpoint 호환성, hook lifecycle, head 교체 시 안전한 partial load를 초음파 CNN 예제로 실습한다.

예상 학습 시간: 35분
난이도: Intermediate
사용 기술: PyTorch 지난 두 회차에서 Tensor Shape와 Gradient Flow를 추적했습니다. 오늘은 그 두 분석이 성립하기 위한 기반인 nn.Module의 등록 시스템을 해부합니다. 모델 객체에 레이어가 “들어 있다”는 것과 PyTorch가 그 레이어를 parameter·device 이동·checkpoint의 대상으로 “알고 있다”는 것은 다릅니다.

1. 학습 목표

오늘 학습을 마치면 다음을 할 수 있어야 합니다.

  • nn.Module이 submodule, parameter, buffer를 추적하는 방식을 설명한다.

  • 일반 Python list와 ModuleList, ModuleDict, Sequential의 차이를 판단한다.

  • nn.Parameter, 일반 Tensor, registered buffer를 용도에 맞게 선택한다.

  • state_dict key가 모델의 속성 경로에서 어떻게 만들어지는지 추적한다.

  • strict=False가 해결하는 문제와 해결하지 못하는 문제를 구분한다.

  • forward hook을 안전하게 등록하고 반드시 해제한다.

  • 출력 head나 block을 바꾸면서 pretrained checkpoint의 호환 가능한 부분만 로드한다.

2. 핵심 이론

2.1 nn.Module은 단순한 Python 객체가 아니다

nn.Module의 핵심 역할은 forward 함수를 제공하는 것만이 아닙니다. 내부적으로 다음 세 종류의 상태를 이름과 함께 등록합니다.

  1. Submodule: nn.Conv2d, nn.Sequential, 사용자 정의 nn.Module 등

  2. Parameter: optimizer가 갱신할 학습 가능한 Tensor

  3. Buffer: 학습하지 않지만 모델과 함께 device를 이동하거나 저장해야 하는 Tensor

self.stem = nn.Conv2d(1, 16, kernel_size=3, padding=1)
self.temperature = nn.Parameter(torch.ones(()))
self.register_buffer("mean", torch.tensor(0.45))

이 세 줄은 각각 _modules, _parameters, _buffers라는 내부 registry에 이름을 등록합니다. 일반적으로 직접 이 dictionary를 수정하지 않고 attribute 할당이나 공식 등록 API를 사용합니다. 중요한 결과는 다음과 같습니다.

  • model.parameters()가 optimizer 대상 parameter를 찾을 수 있습니다.

  • model.to("cuda")가 parameter와 buffer를 함께 옮깁니다.

  • model.train()과 model.eval()이 모든 등록된 자식 모듈에 재귀적으로 전달됩니다.

  • model.state_dict()가 안정적인 이름으로 checkpoint state를 만듭니다. 즉, 등록되지 않은 객체는 forward에서 계산될 수는 있어도 모델 관리 체계 밖에 있습니다. 이것이 가장 위험한 종류의 조용한 버그입니다.

2.2 일반 list와 ModuleList

다음 코드는 Python 문법상 정상입니다.

self.blocks = [
    ConvBlock(16),
    ConvBlock(16),
]

forward에서 반복하면 결과도 나옵니다.

for block in self.blocks:
    x = block(x)

그러나 일반 list 안의 모듈은 부모 nn.Module에 등록되지 않습니다. 그 결과:

  • model.parameters()에서 block parameter가 누락됩니다.

  • optimizer가 해당 weight를 갱신하지 않습니다.

  • model.to(device)가 block을 이동시키지 않습니다.

  • state_dict()에 block weight가 없습니다.

  • train()과 eval() 모드가 block 내부의 BatchNorm·Dropout에 전달되지 않습니다. 수정 방법은 nn.ModuleList입니다.

self.blocks = nn.ModuleList([
    ConvBlock(16),
    ConvBlock(16),
])

ModuleList는 모듈을 등록하지만 실행 순서를 스스로 정의하지 않습니다. forward에서 반복·조건·skip connection을 직접 구현할 수 있습니다. Sequential은 등록과 데이터 흐름을 함께 정의합니다.

self.encoder = nn.Sequential(
    ConvBlock(16),
    ConvBlock(16),
)

선택 기준:

  • 단순 직렬 실행이면 Sequential

  • 반복, 분기, attention, residual 등 사용자 정의 흐름이면 ModuleList

  • 문자열 key로 여러 branch나 head를 선택하면 ModuleDict

2.3 Parameter와 buffer

nn.Parameter

학습을 통해 값이 변해야 하고 gradient를 받아 optimizer가 갱신해야 하는 값입니다.

self.logit_scale = nn.Parameter(torch.tensor(1.0))

attribute에 nn.Parameter를 할당하면 named_parameters()와 state_dict()에 등록됩니다.

일반 Tensor

self.mean = torch.tensor(0.45)

Python attribute로는 존재하지만 parameter도 buffer도 아닙니다. model.to("cuda")를 호출해도 자동 이동하지 않고 state_dict()에도 들어가지 않습니다. CPU에서는 문제없이 실행되다가 GPU에서 device mismatch가 발생할 수 있습니다.

Registered buffer

self.register_buffer(
    "mean",
    torch.tensor(0.45).view(1, 1, 1, 1)
)

학습되지는 않지만 모델 상태의 일부인 Tensor입니다. 예:

  • 입력 정규화 mean/std

  • BatchNorm의 running_mean, running_var

  • 고정된 positional encoding

  • 고정 convolution kernel

  • class weight나 calibration constant 기본값 persistent=True이면 state_dict()에도 포함됩니다. 실행 중 다시 계산할 수 있는 cache처럼 checkpoint에 저장할 필요가 없다면 다음처럼 지정합니다.

self.register_buffer(
    "feature_cache",
    torch.empty(0),
    persistent=False,
)

이 buffer는 device 이동은 따르지만 checkpoint key에는 포함되지 않습니다.

2.4 Module tree를 읽는 API

model.named_children()

바로 아래의 자식 모듈만 반환합니다.

model.named_modules()

자기 자신을 포함해 전체 module tree를 재귀적으로 순회합니다.

model.named_parameters()
model.named_buffers()

각각 등록된 parameter와 buffer를 이름과 함께 반환합니다. 모델 수정 전후에는 총 parameter 수만 비교하지 말고 이름과 shape 목록을 비교하는 편이 좋습니다.

for name, parameter in model.named_parameters():
    print(name, tuple(parameter.shape), parameter.requires_grad)

이름은 attribute 경로를 반영합니다. plain text stem.0.weight blocks.0.conv.weight blocks.1.bn.running_mean head.weight 이 경로가 checkpoint API 계약의 일부가 됩니다. 계산이 같더라도 모듈을 감싸거나 이름을 바꾸면 key가 달라집니다.

2.5 state_dict의 정체

state_dict()는 다음을 포함하는 flat mapping입니다.

  • 등록된 parameter

  • persistent buffer 다음은 포함하지 않습니다.

  • 일반 Tensor attribute

  • persistent=False buffer

  • 일반 list 안의 미등록 module

  • forward 중의 임시 activation

  • Python 설정값 자체

for key, value in model.state_dict().items():
    print(key, tuple(value.shape), value.dtype)

주의: 메모리 안에서 best_state = model.state_dict()만 저장하면 독립적인 snapshot이라고 가정해서는 안 됩니다. 학습을 계속하는 동안 underlying tensor가 바뀔 수 있으므로 파일에 즉시 저장하거나 clone/deepcopy가 필요합니다.

best_state = {
    key: value.detach().cpu().clone()
    for key, value in model.state_dict().items()
}

2.6 load_state_dict: strict의 정확한 의미

result = model.load_state_dict(checkpoint, strict=True)

strict=True는 model key와 checkpoint key가 정확히 일치해야 합니다.

  • model에는 있지만 checkpoint에는 없는 key: missing_keys

  • checkpoint에는 있지만 model에는 없는 key: unexpected_keys strict=False는 missing/unexpected key를 허용하고 결과 객체로 목록을 돌려줍니다.

result = model.load_state_dict(checkpoint, strict=False)
print(result.missing_keys)
print(result.unexpected_keys)

하지만 같은 key의 shape가 다른 문제는 일반적으로 해결하지 못합니다. 예를 들어 head.weight가 [2, 16]에서 [3, 16]으로 바뀌면 해당 key를 먼저 checkpoint에서 제외해야 합니다. 따라서 strict=False는 “대충 로드” 옵션이 아니라, 의도적으로 허용할 key 차이를 검사하기 위한 도구로 사용해야 합니다.

2.7 Hook의 lifecycle

Hook은 원본 forward 코드를 바꾸지 않고 중간 입력·출력·gradient를 관찰할 수 있게 합니다.

  • register_forward_pre_hook: 모듈 forward 직전의 입력

  • register_forward_hook: 모듈 forward 직후의 입력과 출력

  • register_full_backward_hook: 모듈 단위의 grad_input, grad_output

handle = module.register_forward_hook(hook_fn)

등록 함수는 RemovableHandle을 반환합니다. 진단이 끝나면 반드시 해제합니다.

handle.remove()

Jupyter 셀을 반복 실행하면서 hook을 계속 추가하면 한 번의 forward에서 같은 로그가 여러 번 출력될 수 있습니다. Hook 내부에서 activation을 그대로 list에 보관하면 computation graph 참조가 유지되어 메모리 사용이 커질 수도 있습니다. 통계만 필요하다면 output.detach() 또는 scalar 요약을 저장합니다.

3. 실제 모델 구조 분석

초음파 grayscale 입력을 받는 작은 CNN을 사용합니다.

import torch
import torch.nn as nn


class ConvBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv = nn.Conv2d(
            channels, channels, 3,
            padding=1, bias=False
        )
        self.bn = nn.BatchNorm2d(channels)
        self.act = nn.SiLU(inplace=False)

    def forward(self, x):
        return self.act(self.bn(self.conv(x)))


class UltrasoundNet(nn.Module):
    def __init__(self, num_classes=2):
        super().__init__()

        self.stem = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1, bias=False),
            nn.BatchNorm2d(16),
            nn.SiLU(inplace=False),
        )

        self.blocks = nn.ModuleList([
            ConvBlock(16),
            ConvBlock(16),
        ])

        self.register_buffer(
            "input_mean",
            torch.tensor(0.45).view(1, 1, 1, 1),
        )
        self.register_buffer(
            "input_std",
            torch.tensor(0.20).view(1, 1, 1, 1),
        )
        self.register_buffer(
            "feature_cache",
            torch.empty(0),
            persistent=False,
        )

        self.pool = nn.AdaptiveAvgPool2d(1)
        self.head = nn.Linear(16, num_classes)

    def forward(self, x):
        x = (x - self.input_mean) / self.input_std.clamp_min(1e-6)
        x = self.stem(x)

        for block in self.blocks:
            x = x + block(x)

        x = self.pool(x).flatten(1)
        return self.head(x)

등록 tree는 다음과 같습니다. plain text UltrasoundNet ├─ stem: Sequential │ ├─ 0: Conv2d │ ├─ 1: BatchNorm2d │ └─ 2: SiLU ├─ blocks: ModuleList │ ├─ 0: ConvBlock │ │ ├─ conv: Conv2d │ │ ├─ bn: BatchNorm2d │ │ └─ act: SiLU │ └─ 1: ConvBlock ├─ pool: AdaptiveAvgPool2d └─ head: Linear input_mean, input_std는 module tree에는 나타나지 않지만 named_buffers()와 state_dict()에 나타납니다. feature_cache는 named_buffers()에는 있지만 non-persistent이므로 state_dict()에는 없습니다. 등록 상태를 확인하는 최소 점검 코드입니다.

model = UltrasoundNet()

print("[children]")
for name, module in model.named_children():
    print(name, type(module).__name__)

print("\n[buffers]")
for name, buffer in model.named_buffers():
    print(name, tuple(buffer.shape))

print("\n[state_dict]")
for key, value in model.state_dict().items():
    print(key, tuple(value.shape))

4. 수정 가능한 지점과 trade-off

4.1 ModuleList와 Sequential

ModuleList를 사용하면 block별 stochastic depth, conditional branch, deep supervision을 쉽게 넣을 수 있습니다. 반면 forward 흐름이 코드에 흩어져 정적 분석이나 export가 더 까다로울 수 있습니다. Sequential은 단순하고 tooling이 이해하기 쉽지만 입력이 하나에서 하나로 흐르는 구조에 가장 적합합니다. residual이나 여러 tensor를 주고받는 block에는 별도 wrapper가 필요할 수 있습니다.

4.2 Parameter와 buffer

입력 normalization 값이 학습되어야 한다면 Parameter로 바꿀 수 있습니다. 그러나 학습 가능한 normalization은 데이터 분포에 적응하는 장점과 함께 다음 위험을 만듭니다.

  • 값이 불안정하게 변해 입력 scale이 무너질 수 있음

  • pretrained checkpoint와 전처리 계약이 달라짐

  • optimizer weight decay 적용 여부를 별도로 설계해야 함 고정 통계는 buffer, 학습 대상은 Parameter라는 의미 구분을 유지해야 합니다.

4.3 Persistent buffer

통계나 calibration 값처럼 재현에 필요한 상태는 persistent buffer가 적합합니다. 크기가 큰 cache를 persistent로 저장하면 checkpoint가 불필요하게 커지고 오래된 cache가 복원될 수 있습니다. 반대로 재현에 필요한 값을 non-persistent로 두면 재시작 후 결과가 달라질 수 있습니다.

4.4 Attribute 이름과 checkpoint 호환성

self.head = nn.Linear(16, 2)

을 다음처럼 감싸면:

self.head = nn.Sequential(nn.Linear(16, 2))

계산은 거의 같지만 key가 head.weight에서 head.0.weight로 바뀝니다. 장기 운영 모델에서는 module 경로를 public API처럼 관리하거나 checkpoint migration 함수를 제공해야 합니다.

4.5 strict=False

장점은 backbone 재사용과 head 교체가 쉽다는 것입니다. 위험은 예상하지 않은 parameter 누락도 조용히 허용한다는 점입니다. 실제 코드에서는 허용 가능한 missing key를 assertion으로 제한합니다.

result = model.load_state_dict(checkpoint, strict=False)
assert all(k.startswith("head.") for k in result.missing_keys)
assert not result.unexpected_keys

4.6 Hook과 명시적 forward

Hook은 관찰·디버깅에 좋지만 핵심 학습 로직이나 feature routing을 hook에 의존하면 실행 순서가 숨겨지고 torch.compile, export, 분산 실행에서 관리가 어려워질 수 있습니다. 모델 동작은 가능하면 forward에 명시하고, hook은 진단용으로 제한합니다.

5. 직접 실행 실습

실습 A: 미등록 module 버그 재현

import torch
import torch.nn as nn


class BrokenNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = nn.Conv2d(1, 8, 3, padding=1)

        # 부모 모델에 등록되지 않는다.
        self.blocks = [
            nn.Conv2d(8, 8, 3, padding=1),
            nn.Conv2d(8, 8, 3, padding=1),
        ]

        # 자동 device 이동·checkpoint 저장 대상이 아니다.
        self.mean = torch.tensor(0.45)

    def forward(self, x):
        x = self.stem(x - self.mean)
        for block in self.blocks:
            x = block(x)
        return x


class FixedNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = nn.Conv2d(1, 8, 3, padding=1)

        self.blocks = nn.ModuleList([
            nn.Conv2d(8, 8, 3, padding=1),
            nn.Conv2d(8, 8, 3, padding=1),
        ])

        self.register_buffer("mean", torch.tensor(0.45))

    def forward(self, x):
        x = self.stem(x - self.mean)
        for block in self.blocks:
            x = block(x)
        return x


def report(model):
    print(f"\n[{type(model).__name__}]")
    print("parameter names:")
    for name, parameter in model.named_parameters():
        print(" ", name, tuple(parameter.shape))

    print("buffer names:")
    for name, buffer in model.named_buffers():
        print(" ", name, tuple(buffer.shape))

    print("state_dict keys:")
    for key in model.state_dict():
        print(" ", key)


broken = BrokenNet()
fixed = FixedNet()

report(broken)
report(fixed)

예상 결과:

  • BrokenNet에는 stem.weight, stem.bias만 등록됩니다.

  • BrokenNet.blocks.0/1의 weight는 출력에 없습니다.

  • BrokenNet.mean은 buffer와 state_dict에 없습니다.

  • FixedNet에는 blocks.0.weight, blocks.1.weight, mean이 모두 나타납니다. CUDA가 있다면 device 문제도 확인합니다.

if torch.cuda.is_available():
    broken = BrokenNet().cuda()
    fixed = FixedNet().cuda()
    x = torch.randn(2, 1, 32, 32, device="cuda")

    try:
        broken(x)
    except RuntimeError as error:
        print("BrokenNet error:", error)

    y = fixed(x)
    print("FixedNet output device:", y.device)

BrokenNet은 CPU에 남아 있는 mean 또는 list 내부 convolution 때문에 device mismatch가 발생합니다.

실습 B: Hook으로 shape 추적 후 해제

import torch
import torch.nn as nn


model = UltrasoundNet(num_classes=2)
records = []
handles = []


def make_hook(name):
    def hook(module, inputs, output):
        input_shape = tuple(inputs[0].shape)
        output_shape = tuple(output.shape)
        records.append((name, input_shape, output_shape))
    return hook


for name, module in model.named_modules():
    if isinstance(module, (nn.Conv2d, nn.AdaptiveAvgPool2d, nn.Linear)):
        handles.append(module.register_forward_hook(make_hook(name)))


with torch.no_grad():
    logits = model(torch.randn(2, 1, 64, 64))

for name, input_shape, output_shape in records:
    print(f"{name:20s} {input_shape} -> {output_shape}")

print("logits:", tuple(logits.shape))

for handle in handles:
    handle.remove()

before = len(records)

with torch.no_grad():
    model(torch.randn(2, 1, 64, 64))

print("new records after remove:", len(records) - before)

예상 결과:

  • convolution의 spatial shape는 [64, 64]로 유지됩니다.

  • pool 출력은 [2, 16, 1, 1]입니다.

  • head 출력은 [2, 2]입니다.

  • handle을 제거한 뒤 추가 record 수는 0입니다.

실습 C: Head 교체와 안전한 partial load

import torch


source = UltrasoundNet(num_classes=2)

# 독립적인 메모리 snapshot
checkpoint = {
    key: value.detach().cpu().clone()
    for key, value in source.state_dict().items()
}

target = UltrasoundNet(num_classes=3)
target_state = target.state_dict()


def compatible_state_dict(checkpoint, model_state):
    compatible = {}
    mismatched = {}
    unexpected = []

    for key, value in checkpoint.items():
        if key not in model_state:
            unexpected.append(key)
        elif value.shape != model_state[key].shape:
            mismatched[key] = (
                tuple(value.shape),
                tuple(model_state[key].shape),
            )
        else:
            compatible[key] = value

    return compatible, mismatched, unexpected


compatible, mismatched, unexpected = compatible_state_dict(
    checkpoint,
    target_state,
)

print("mismatched:", mismatched)
print("unexpected:", unexpected)

result = target.load_state_dict(compatible, strict=False)

print("missing:", result.missing_keys)
print("unexpected after load:", result.unexpected_keys)

assert set(result.missing_keys) == {"head.weight", "head.bias"}
assert not result.unexpected_keys

with torch.no_grad():
    output = target(torch.randn(2, 1, 64, 64))

print("new output shape:", tuple(output.shape))

예상 결과:

  • head.weight: checkpoint [2, 16], target [3, 16]

  • head.bias: checkpoint [2], target [3]

  • 나머지 backbone과 buffer는 정상 로드

  • 새 출력 shape는 [2, 3]

선택 과제: Optimizer가 모든 parameter를 보는지 검증

def trainable_parameter_ids(model):
    return {
        id(parameter)
        for parameter in model.parameters()
        if parameter.requires_grad
    }


def optimizer_parameter_ids(optimizer):
    return {
        id(parameter)
        for group in optimizer.param_groups
        for parameter in group["params"]
    }


model = UltrasoundNet()
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

missing = trainable_parameter_ids(model) - optimizer_parameter_ids(optimizer)
extra = optimizer_parameter_ids(optimizer) - trainable_parameter_ids(model)

print("missing trainable parameters:", len(missing))
print("extra optimizer parameters:", len(extra))

둘 다 0이어야 합니다. 모델을 만든 뒤 parameter를 새로 추가하거나 optimizer 생성 후 모듈을 교체했다면 이 검사가 실패할 수 있습니다. 그 경우 optimizer를 다시 구성하거나 의도적으로 새 parameter group을 추가해야 합니다.

권장 진단 순서

  1. named_parameters()와 named_buffers()의 이름·shape·device를 출력합니다.

  2. 모델과 checkpoint의 key 집합 차이를 계산합니다.

  3. 공통 key는 shape와 dtype까지 비교합니다.

  4. 허용할 missing/unexpected key를 명시적으로 assertion합니다.

  5. optimizer가 모든 trainable parameter를 포함하는지 확인합니다.

  6. hook은 좁은 모듈에만 등록하고 try/finally 또는 context manager 형태로 해제합니다.

  7. 수정 후 작은 입력으로 forward와 backward 한 step을 실행합니다.

  8. 저장한 checkpoint를 새 Python process에서 다시 로드해 재현성을 검증합니다.

실무 체크포인트

모델 구조를 바꿀 때는 정확도 실험 전에 다음 네 가지 계약을 먼저 확인합니다.

  • Registration 계약: 학습할 모듈과 parameter가 모두 등록되었는가?

  • Device 계약: parameter와 buffer가 입력과 같은 device/dtype에 있는가?

  • Checkpoint 계약: key 이름과 shape 변경이 의도된 것인가?

  • Execution 계약: hook이나 wrapper가 forward 의미를 몰래 바꾸지 않는가? 이 네 가지가 깨지면 학습률이나 loss function을 조정해도 원인을 해결할 수 없습니다.

7. 복습 문제

  1. forward()에서 정상 실행되는 convolution이 model.parameters()에는 나타나지 않을 수 있는 대표적인 이유는 무엇인가요?

  2. 학습되지는 않지만 model.to("cuda")와 checkpoint 저장을 모두 따라야 하는 Tensor에는 어떤 등록 방식을 사용해야 하나요?

  3. ModuleList와 Sequential의 핵심 차이는 무엇인가요?

  4. 출력 class 수를 2에서 3으로 바꾼 뒤 strict=False만 사용해도 head.weight의 shape mismatch가 자동으로 무시되나요?

  5. Jupyter에서 forward hook을 여러 번 등록한 뒤 로그가 중복되고 메모리가 늘어납니다. 무엇을 확인하고 어떻게 수정해야 하나요?

정답과 해설

  1. 일반 Python list나 dict 안에 모듈을 넣어 부모 nn.Module에 등록하지 않았을 가능성이 큽니다. ModuleList 또는 ModuleDict를 사용하거나 attribute로 직접 할당해야 합니다.

  2. register_buffer(name, tensor, persistent=True)를 사용합니다. Buffer는 optimizer 대상은 아니지만 model의 device 이동을 따르고 persistent이면 state_dict에 저장됩니다.

  3. 두 container 모두 모듈을 등록합니다. Sequential은 모듈을 순서대로 실행하는 forward 흐름까지 제공하지만 ModuleList는 등록만 하므로 반복·분기·residual 흐름을 사용자가 forward에서 작성합니다.

  4. 아닙니다. strict=False는 missing/unexpected key를 허용하지만 동일한 key의 tensor shape 불일치는 별도로 필터링해야 합니다. 호환되지 않는 head.weight와 head.bias를 checkpoint에서 제외한 뒤 결과의 missing key가 그 둘뿐인지 검사합니다.

  5. hook 등록이 반환한 RemovableHandle을 보관하고 handle.remove()를 호출했는지 확인합니다. Hook 안에서는 graph가 붙은 activation 전체 대신 detach()한 값이나 shape·mean 같은 요약만 저장합니다. 반복 실행 전 기존 handle도 정리해야 합니다.
