AI 전문 개발 학습 #03 — nn.Module 내부 구조 완전 해부

Parameter·buffer·ModuleList·state_dict의 등록 구조를 이해하고 hook 기반 모델 분석기를 구현합니다.

예상 학습시간: 60분

이제 중요한 단계입니다.

다음 코드를 보겠습니다.

class MyModel(nn.Module):

    def __init__(self):
        super().__init__()

        self.conv1 = nn.Conv2d(1, 32, 3)
        self.conv2 = nn.Conv2d(32, 64, 3)

    def forward(self, x):

        x = self.conv1(x)
        x = self.conv2(x)

        return x

겉으로는 간단합니다.

하지만 내부적으로는 상당히 많은 일이 일어납니다.

1. nn.Module이 관리하는 것

PyTorch에서 Module은 neural network의 기본 building block이며 autograd, parameter 관리, device 이동, save/load 등의 기능과 긴밀하게 통합되어 있습니다.

우리가:

self.conv1 = nn.Conv2d(...)

라고 쓰면 단순한 Python attribute 저장 이상의 의미를 가집니다.

Module hierarchy에 submodule이 등록됩니다.

그래서:

model.parameters()

가 conv1과 conv2의 parameter를 찾아낼 수 있습니다.

2. Parameter

예를 들어 직접 parameter를 만들 수도 있습니다.

class MyLayer(nn.Module):

    def __init__(self):

        super().__init__()

        self.weight = nn.Parameter(
            torch.randn(10, 10)
        )

그러면:

list(model.parameters())

에 weight가 포함됩니다.

optimizer 역시:

optimizer = Adam(model.parameters())

를 통해 이를 받습니다.

3. 가장 중요한 함정: Python list

이 코드를 보겠습니다.

self.layers = [
    nn.Linear(100,100),
    nn.Linear(100,100),
    nn.Linear(100,100)
]

겉보기에는 정상입니다.

하지만 이런 경우에는 submodule 등록 측면에서 문제가 생길 수 있습니다.

그래서 PyTorch에서는:

self.layers = nn.ModuleList([
    nn.Linear(100,100),
    nn.Linear(100,100),
    nn.Linear(100,100)
])

를 사용합니다.

ModuleList 내부의 module은 nn.Module에 제대로 등록되어 module 관련 메서드에서 인식됩니다.

이 차이는 custom architecture를 만들 때 매우 중요합니다.

4. Parameter vs Buffer

여기서 상당히 중요한 개념이 나옵니다.

Parameter

와

Buffer

입니다.

Parameter

학습 대상:

Conv weight
Linear weight
bias

등입니다.

Buffer

모델 상태에는 포함되지만 일반적으로 gradient로 학습하는 parameter가 아닌 값입니다.

대표적으로 BatchNorm의:

running_mean
running_var

가 있습니다.

PyTorch에서는:

self.register_buffer(
    "running_mean",
    torch.zeros(64)
)

처럼 등록할 수 있습니다.

persistent buffer는 기본적으로 state_dict에도 포함됩니다.

5. 왜 이게 중요한가?

Fine-tuning할 때 이런 코드를 자주 봅니다.

for p in backbone.parameters():
    p.requires_grad = False

그러면 질문:

BatchNorm running_mean도 멈출까요?

반드시 그렇다고 볼 수 없습니다.

parameter gradient를 freeze하는 것과 BatchNorm의 running statistics 업데이트는 별개의 문제입니다.

그래서 fine-tuning에서는:

model.train()

과

model.eval()

의 차이가 중요합니다.

이 문제는 작은 의료 데이터셋에서 특히 중요합니다.

6. state_dict

모델을 저장할 때:

torch.save(
    model.state_dict(),
    "model.pth"
)

를 많이 사용했을 것입니다.

state_dict()는 단순 weight collection이라고만 이해하면 부족합니다.

PyTorch Module의 state에는 parameter와 persistent buffer가 포함됩니다.

확인해 봅시다.

for key in model.state_dict():
    print(key)

예:

conv1.weight
conv1.bias

bn1.weight
bn1.bias
bn1.running_mean
bn1.running_var

conv2.weight
conv2.bias

여기서:

bn1.running_mean
bn1.running_var

는 optimizer가 학습시키는 일반 parameter가 아닙니다.

7. Pretrained model 수정

여기부터 실무적으로 매우 중요합니다.

예를 들어 pretrained model이:

Backbone
 ├─ block1
 ├─ block2
 ├─ block3
 └─ classifier

이고 classifier가:

nn.Linear(2048, 1000)

이라고 합시다.

우리는 ultrasound classification에서 3 classes가 필요합니다.

그러면:

model.fc = nn.Linear(
    model.fc.in_features,
    3
)

처럼 바꿉니다.

하지만 기존 checkpoint에는:

fc.weight → [1000,2048]

가 있습니다.

새 모델은:

fc.weight → [3,2048]

입니다.

따라서 checkpoint compatibility 문제가 생깁니다.

8. strict=False를 무조건 믿으면 안 되는 이유

보통:

model.load_state_dict(
    checkpoint,
    strict=False
)

를 사용합니다.

하지만 더 좋은 습관은 결과를 반드시 확인하는 것입니다.

result = model.load_state_dict(
    checkpoint,
    strict=False
)

print(result.missing_keys)
print(result.unexpected_keys)

PyTorch의 load_state_dict()는 이러한 missing_keys와 unexpected_keys를 반환합니다. strict=True에서는 state_dict의 key가 모델과 정확히 일치해야 합니다.

9. Forward Hook

이제 아주 강력한 도구입니다.

모델 코드를 수정하지 않고 중간 feature를 볼 수 있습니다.

features = {}

def hook_fn(module, input, output):
    features["layer3"] = output.detach()

handle = model.layer3.register_forward_hook(
    hook_fn
)

forward:

output = model(x)

이후:

print(features["layer3"].shape)

로 중간 activation을 확인할 수 있습니다.

forward hook은 forward() 계산 후 호출됩니다.

10. 모델 자동 분석기

이제 지금까지 배운 내용을 이용해 꽤 유용한 코드를 만들 수 있습니다.

def hook(name):

    def fn(module, inputs, output):

        if isinstance(output, torch.Tensor):

            print(
                f"{name:30s}",
                list(output.shape)
            )

    return fn


handles = []

for name, module in model.named_modules():

    if isinstance(
        module,
        (
            nn.Conv2d,
            nn.Linear,
            nn.BatchNorm2d
        )
    ):

        h = module.register_forward_hook(
            hook(name)
        )

        handles.append(h)

그리고:

x = torch.randn(
    1, 1, 256, 256
)

output = model(x)

실행하면:

encoder.conv1     [1,32,256,256]

encoder.bn1       [1,32,256,256]

encoder.conv2     [1,64,128,128]

encoder.bn2       [1,64,128,128]

encoder.conv3     [1,128,64,64]

처럼 볼 수 있습니다.

이것은 상당히 중요한 개발 도구입니다.

11. 여기서 한 단계 더 발전

단순 shape뿐 아니라:

def hook(name):

    def fn(module, inputs, output):

        print(
            name,
            output.shape,
            output.mean().item(),
            output.std().item(),
            output.min().item(),
            output.max().item()
        )

    return fn

으로 만들 수 있습니다.

그러면 layer마다:

shape
mean
std
min
max

를 확인할 수 있습니다.

12. 이것이 왜 중요한가?

예를 들어 모델이 학습되지 않습니다.

중간 activation을 조사했더니:

layer1 std = 0.42
layer2 std = 0.31
layer3 std = 0.08
layer4 std = 0.002
layer5 std = 0.00001

이라면?

feature가 점점 collapse하고 있을 가능성을 조사해야 합니다.

반대로:

0.3
1.2
8.7
92
1700

처럼 커진다면 exploding activation 가능성을 의심할 수 있습니다.

즉:

Loss만 보는 것에서 벗어나 모델 내부를 관찰하기 시작하는 것입니다.

13. Gradient까지 결합

forward hook:

activation 분석

backward hook:

gradient 분석

을 함께 사용할 수 있습니다.

PyTorch는 register_full_backward_hook()을 제공하며 module의 gradient가 계산될 때 hook을 실행할 수 있습니다.

따라서:

               Forward
Input ─────────────────────→ Loss

        activation 확인
             ↓

Input ←───────────────────── Loss
              Backward

         gradient 확인
             ↑

이 가능합니다.

14. AI 개발자가 가져야 할 Debugging 사고

이제부터는:

Loss 안 내려감
    ↓
LR 변경

식으로 접근하지 않습니다.

다음처럼 접근합니다.

Loss 이상

 ├─ Data?

이 사고방식이 이번 3회차의 가장 중요한 결과입니다.

종합 실습

class UltrasoundNet(nn.Module):

    def __init__(self):

        super().__init__()

        self.encoder = nn.ModuleList([

            nn.Conv2d(1, 32, 3, 2, 1),
            nn.Conv2d(32, 64, 3, 2, 1),
            nn.Conv2d(64, 128, 3, 2, 1)

        ])

        self.pool = nn.AdaptiveAvgPool2d(1)

        self.fc = nn.Linear(128, 2)


    def forward(self, x):

        for layer in self.encoder:

            x = F.relu(layer(x))

        x = self.pool(x)

        x = torch.flatten(x, 1)

        return self.fc(x)

그런데 여기서 더 중요한 질문을 던져야 합니다.

Q1. 5 mm짜리 작은 병변을 탐지해야 한다면 stride=2를 세 번 적용하는 것이 적절한가?

반드시 그렇지는 않습니다. 작은 병변 정보가 지나치게 일찍 손실될 가능성을 검토해야 합니다.

Q2. Classification이 아니라 detection이면?

Global Average Pooling으로 spatial 정보를 제거해서는 detection 위치를 직접 얻기 어렵습니다.

Q3. pretrained model이라면?

초음파 grayscale [B,1,H,W]와 ImageNet RGB [B,3,H,W] 입력 차이를 처리해야 합니다.

예:

x = x.repeat(1,3,1,1)

또는 첫 Conv를:

Conv2d(3,...)

에서

Conv2d(1,...)

으로 변경하는 방법 등을 검토해야 합니다.

하지만 후자의 경우 pretrained weight를 어떻게 변환할지도 결정해야 합니다.

Q4

왜 다음보다:

self.layers = [
    nn.Conv2d(...),
    nn.Conv2d(...)
]

다음을 사용하는가?

self.layers = nn.ModuleList([
    nn.Conv2d(...),

정답

ModuleList 내부 module은 PyTorch의 module hierarchy에 올바르게 등록되어 parameters(), state_dict(), device 이동 등의 Module 기능에 제대로 참여합니다.
