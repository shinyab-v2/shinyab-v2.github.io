ONNX Graph
PyTorch code를 Operator Graph로 읽기

deployment에서 모델은 Python class가 아니라 operator와 tensor edge의 graph가 됩니다. export, dynamic shape, graph inspection, numerical validation을 실습합니다.

1. 왜 ONNX를 배우는가?

PyTorch의 forward()는 Python 실행 문맥을 포함하지만 inference engine은 보통 tensor 연산 graph를 원합니다. ONNX는 모델의 operator, tensor, initializer, shape 정보를 교환 가능한 graph 형태로 표현합니다.

2. 최소 export

model.eval()
x = torch.randn(1, 1, 224, 224)

torch.onnx.export(
    model, x, 'model.onnx',
    input_names=['image'],
    output_names=['logits'],
    opset_version=18,
)

실제 사용 API와 권장 exporter 옵션은 사용 중인 PyTorch 버전에 따라 달라질 수 있으므로 프로젝트 버전 문서를 확인해야 합니다.

3. Graph의 구성요소

Node는 Conv, Relu, Add 같은 operator이고, Edge는 tensor입니다. Initializer는 weight/bias처럼 graph에 저장되는 parameter입니다. Python의 module hierarchy와 ONNX node hierarchy가 1:1로 대응한다고 가정하면 안 됩니다.

4. Shape를 먼저 본다

import onnx
m = onnx.load('model.onnx')
onnx.checker.check_model(m)
for i in m.graph.input:
    print('input:', i.name, i.type)
for o in m.graph.output:
    print('output:', o.name, o.type)

Detection 모델은 특히 batch, image H/W, detection count가 동적일 수 있으므로 static/dynamic shape 정책을 deployment 전에 명확히 해야 합니다.

5. Dynamic shape의 의미

“dynamic을 켠다”는 공짜 유연성이 아닙니다. runtime optimization 범위를 넓히거나 제한할 수 있고 TensorRT에서는 optimization profile 설계와 연결됩니다. 실제 서비스 입력 크기가 고정이라면 static shape가 더 단순하고 빠를 수 있습니다.

6. Unsupported operator

export 실패 또는 TensorRT 변환 실패 시 “ONNX가 안 된다”로 끝내지 말고 어떤 node가 문제인지 확인합니다. custom grid_sample, deformable op, 특정 NMS처럼 runtime 지원 여부가 중요한 연산이 대표적입니다.

7. Numerical equivalence

with torch.no_grad():
    y_pt = model(x).cpu().numpy()

# ONNX Runtime 결과 y_ort와 비교
abs_err = np.max(np.abs(y_pt - y_ort))
rel_err = np.max(np.abs(y_pt-y_ort)/(np.abs(y_pt)+1e-6))
print(abs_err, rel_err)

단순히 export 성공만 확인하지 말고 동일 입력에서 output이 허용 오차 내에 있는지 검증합니다.

Developer Insight: deployment debugging은 “모델 파일 생성 성공”이 아니라 PyTorch → ONNX → target runtime의 각 경계에서 shape와 numerical equivalence를 검증하는 작업입니다.

8. Ultrasound 적용

초음파 모델은 grayscale 입력, variable resolution, preprocessing normalization이 inference pipeline과 정확히 일치하는지 특히 중요합니다. ONNX graph만 맞아도 preprocessing이 달라지면 임상 성능은 달라질 수 있습니다.

9. 실습

  1. 작은 CNN을 ONNX로 export합니다.
  2. graph node 종류를 출력합니다.
  3. Netron 같은 graph viewer로 Conv/Add/Resize 흐름을 확인합니다.
  4. PyTorch와 ONNX Runtime output 오차를 계산합니다.
  5. batch 또는 H/W dynamic 여부를 바꿔 차이를 기록합니다.

10. 복습 문제

  1. ONNX Node와 PyTorch Module은 항상 1:1인가? 아니다.
  2. initializer는 무엇인가? weight/bias 같은 저장 tensor.
  3. dynamic shape가 항상 좋은가? 아니다.
  4. export 성공 후 무엇을 검증해야 하나? shape와 numerical equivalence.
  5. runtime이 특정 op를 지원하지 않으면? graph 수정, 대체 op 또는 custom implementation을 검토한다.
