AI 전문 개발 학습 #02 — Autograd와 Gradient Flow 추적

동적 계산 그래프와 reverse-mode autodiff를 이해하고 leaf/non-leaf tensor, detach·no_grad·retain_grad를 구분한다. Residual block의 backward 경로와 parameter/activation gradient norm을 추적해 단절·소실·폭주를 진단한다.

예상 학습 시간: 35분 지난 회차의 tensor shape 추적에서 한 단계 더 나아가, forward 연산이 어떤 계산 그래프를 만들고 loss의 gradient가 각 레이어로 어떻게 전달되는지 추적합니다.

1. 학습 목표

  • 동적 계산 그래프, leaf/non-leaf tensor, grad_fn의 관계를 설명한다.

  • chain rule과 reverse-mode autodiff를 모델의 backward 경로에 연결한다.

  • requires_grad, detach, no_grad, retain_grad의 차이를 구분한다.

  • residual block에서 identity path가 gradient flow를 개선하는 이유를 Jacobian 관점에서 설명한다.

  • parameter 및 intermediate activation의 gradient norm을 측정하여 단절·소실·폭주를 진단한다.

  • 레이어 동결, activation 교체, loss 가중치 변경 시 학습 동작의 trade-off를 판단한다.

2. 핵심 이론

2.1 계산 그래프는 forward 실행 중 만들어진다

PyTorch Autograd는 Python 코드가 실행되는 순간 실제 tensor 연산을 기록하는 동적 계산 그래프입니다. 조건문이나 반복문에서 이번 forward에 실행된 경로만 그래프에 포함됩니다. 간단한 예를 생각해 봅시다. y = wx + b,   L = (y−t)2 chain rule에 의해 $ \frac{\partial L}{\partial w} = \frac{\partial L}{\partial y} \frac{\partial y}{\partial w} = 2(y-t)x $ 입니다. Autograd는 이 국소 미분들을 연산 노드마다 보관한 뒤 loss에서 입력 방향으로 역순으로 결합합니다.

2.2 Reverse-mode와 VJP

신경망은 입력과 parameter가 많지만 최종 loss는 대개 scalar입니다. 전체 Jacobian을 직접 만들면 메모리와 계산량이 매우 큽니다. Reverse-mode autodiff는 upstream gradient 벡터 v와 Jacobian J의 곱인 vector–Jacobian product를 역방향으로 계산합니다. 선형층 z = Wx + b에서 upstream gradient를 g_z = ∂L/∂z라 하면: $ \frac{\partial L}{\partial W}=g_z x^T,\qquad \frac{\partial L}{\partial x}=W^T g_z $ 따라서 backward는 단순히 “loss를 미분한다”가 아니라, 각 연산이 받은 upstream gradient를 자신의 입력과 parameter 방향으로 변환해 전달하는 과정입니다.

2.3 Leaf와 non-leaf tensor

  • Leaf tensor: 사용자가 직접 만든 requires_grad=True tensor 또는 nn.Parameter. 일반적으로 optimizer가 갱신하는 대상입니다.

  • Non-leaf tensor: 연산 결과로 생성된 activation. 보통 grad_fn을 갖습니다.

  • loss.backward() 후 leaf tensor의 gradient는 .grad에 누적됩니다.

  • non-leaf activation의 .grad는 기본적으로 보존되지 않습니다. 확인하려면 forward 중 retain_grad()를 호출해야 합니다. tensor.grad is None은 항상 gradient가 0이라는 뜻이 아닙니다. 기록 대상이 아니거나, 아직 backward하지 않았거나, 그래프와 연결되지 않았거나, zero_grad(set_to_none=True) 직후일 수 있습니다.

2.4 Gradient 누적

PyTorch는 여러 backward 결과를 .grad에 더합니다. 이는 gradient accumulation에는 유용하지만, 일반 학습 loop에서 초기화를 빼먹으면 의도하지 않은 누적이 됩니다. 권장 순서:

  1. optimizer.zero_grad(set_to_none=True)

  2. forward

  3. loss 계산

  4. loss.backward()

  5. 필요 시 gradient clipping

  6. optimizer.step() set_to_none=True는 불필요한 zero fill을 줄이며, gradient가 실제로 계산되지 않은 parameter를 식별하는 데도 편리합니다.

2.5 requires_grad, detach, no_grad

  • requires_grad_(False): 특정 parameter를 동결합니다.

  • x.detach(): 같은 storage를 공유하지만 현재 계산 그래프에서 분리된 tensor를 반환합니다. 해당 경계 이전으로 gradient가 흐르지 않습니다.

  • with torch.no_grad(): 블록 안의 연산 기록을 끕니다. 추론이나 EMA update처럼 미분이 불필요한 계산에 사용합니다.

  • model.eval(): Dropout과 BatchNorm의 동작 모드를 바꿀 뿐 Autograd를 끄지 않습니다.

  • torch.inference_mode(): 추론 전용 최적화를 더 강하게 적용합니다. 이후 gradient 계산에 재사용할 tensor가 필요한 코드에서는 no_grad()가 더 안전할 수 있습니다.

2.6 Residual connection의 gradient

Residual block을 y = x + F(x) 라고 하면 $ \frac{\partial y}{\partial x}=I+J_F $ 입니다. backward gradient에는 복잡한 F 경로뿐 아니라 identity 행렬을 통한 직접 경로가 존재합니다. 깊은 네트워크에서 gradient가 항상 유지된다는 보장은 없지만, 순수하게 여러 Jacobian만 곱하는 구조보다 전달 경로가 안정적입니다.

3. 실제 모델 구조 분석

아래 block은 초음파 단일 채널 영상을 받는 작은 residual classifier의 핵심입니다.

class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn1 = nn.BatchNorm2d(channels)
        self.act = nn.ReLU(inplace=False)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn2 = nn.BatchNorm2d(channels)

    def forward(self, x):
        identity = x
        h = self.conv1(x)
        h = self.bn1(h)
        h = self.act(h)
        h = self.conv2(h)
        h = self.bn2(h)
        return self.act(identity + h)

3.1 Forward 경로

x → conv1 → bn1 → ReLU → conv2 → bn2 → add(x) → ReLU shape가 같아야 add가 가능하고, x는 main branch와 identity branch 두 경로로 사용됩니다.

3.2 Backward 경로

출력 gradient는 마지막 ReLU mask를 통과한 뒤 add에서 두 갈래로 나뉩니다.

  • identity branch: 입력 x로 직접 전달

  • main branch: bn2 → conv2 → ReLU → bn1 → conv1 순으로 전달 두 경로의 입력 gradient는 x에서 합쳐집니다. 따라서 한 parameter의 gradient가 비정상이라면 forward 순서가 아니라 backward 순서로 어느 지점부터 변화했는지 추적해야 합니다.

3.3 확인할 객체

  • parameter: model.block.conv1.weight.grad

  • non-leaf activation: forward에서 h.retain_grad() 후 h.grad

  • graph 연결: tensor.requires_grad, tensor.grad_fn

  • layer 단위: backward hook

  • 전체 분포: parameter별 gradient norm, zero 비율, NaN/Inf 여부

4. 수정 가능한 지점과 설계 trade-off

4.1 ReLU → SiLU

  • 장점: 음수 영역에서도 완전히 0이 아닌 gradient가 존재하여 dead activation을 줄일 수 있습니다.

  • 비용: ReLU보다 계산이 복잡하며 양자화·일부 배포 backend에서 최적화 차이가 날 수 있습니다.

  • 판단: 정확도뿐 아니라 TensorRT 변환 후 latency까지 측정합니다.

4.2 Post-activation → Pre-activation residual block

  • Post-activation: Conv-BN-Act-Conv-BN-Add-Act

  • Pre-activation: BN-Act-Conv-BN-Act-Conv-Add Pre-activation은 깊은 모델에서 identity 경로를 더 깨끗하게 유지할 수 있지만, pretrained weight를 그대로 옮길 수 없고 activation 통계가 달라집니다.

4.3 Backbone 동결

초음파 데이터가 작을 때 초기 레이어를 동결하면 과적합과 메모리 사용을 줄일 수 있습니다. 그러나 ImageNet RGB texture와 초음파 speckle의 domain gap이 크면 low-level filter까지 적응해야 할 수 있습니다. 동결 후에는:

  • requires_grad=False 여부 확인

  • optimizer를 다시 구성해 불필요한 state 제거

  • BatchNorm running statistics를 계속 갱신할지 결정 해야 합니다. parameter 동결과 BatchNorm의 train/eval 모드는 별개의 문제입니다.

4.4 detach()로 보조 branch 차단

Teacher–student, pseudo-label, target network에서는 한 branch로 gradient가 흐르지 않아야 하므로 detach()가 의도적일 수 있습니다. 반면 feature fusion 직전에 실수로 detach하면 upstream backbone은 조용히 학습을 멈춥니다. 코드가 실행된다는 사실만으로 gradient 연결을 보장할 수 없습니다.

4.5 Loss 가중치

L = L_cls + λL_aux에서 λ는 loss 숫자만 바꾸는 것이 아니라 공유 backbone으로 들어가는 gradient의 방향과 크기를 바꿉니다. 두 loss의 값이 비슷해도 gradient norm은 크게 다를 수 있습니다. multi-task 모델에서는 loss 값과 함께 공유 layer에 대한 task별 gradient norm을 비교해야 합니다.

5. 직접 실행 실습

실습 A — 수식과 Autograd 일치 확인

import torch

torch.manual_seed(7)

x = torch.tensor(3.0)
t = torch.tensor(10.0)
w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(1.0, requires_grad=True)

y = w * x + b
loss = (y - t) ** 2
loss.backward()

manual_dw = 2 * (y.detach() - t) * x
manual_db = 2 * (y.detach() - t)

print("y:", y.item())
print("loss:", loss.item())
print("autograd dw:", w.grad.item(), "manual dw:", manual_dw.item())
print("autograd db:", b.grad.item(), "manual db:", manual_db.item())
print("y.is_leaf:", y.is_leaf, "y.grad_fn:", type(y.grad_fn).__name__)

예상 결과:

  • y = 7, loss = 9

  • dL/dw = -18

  • dL/db = -6

  • y는 non-leaf이고 grad_fn을 가집니다.

실습 B — residual CNN의 gradient flow 측정

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(7)

class ResidualBlock(nn.Module):
    def __init__(self, channels, detach_main=False):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn1 = nn.BatchNorm2d(channels)
        self.act = nn.ReLU(inplace=False)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn2 = nn.BatchNorm2d(channels)
        self.detach_main = detach_main
        self.saved_main = None

    def forward(self, x):
        identity = x
        h = self.conv1(x)
        h = self.bn1(h)
        h = self.act(h)
        h = self.conv2(h)
        h = self.bn2(h)

        if self.detach_main:
            h = h.detach()
        elif h.requires_grad:
            h.retain_grad()

        self.saved_main = h
        return self.act(identity + h)


class TinyUSNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.stem = nn.Sequential(
            nn.Conv2d(1, 8, 3, padding=1, bias=False),
            nn.BatchNorm2d(8),
            nn.ReLU(inplace=False),
        )
        self.block = ResidualBlock(8)
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.head = nn.Linear(8, 2)

    def forward(self, x):
        x = self.stem(x)
        x = self.block(x)
        x = self.pool(x).flatten(1)
        return self.head(x)


def grad_report(model):
    rows = []
    for name, p in model.named_parameters():
        if p.grad is None:
            rows.append((name, None, None))
        else:
            rows.append((
                name,
                p.grad.norm().item(),
                torch.isfinite(p.grad).all().item(),
            ))
    return rows


def run_step(model, x, target):
    model.zero_grad(set_to_none=True)
    with torch.autograd.detect_anomaly():
        logits = model(x)
        loss = F.cross_entropy(logits, target)
        loss.backward()

    print(f"loss={loss.item():.6f}")
    for name, norm, finite in grad_report(model):
        print(f"{name:28s} norm={str(norm):>18s} finite={finite}")

    h = model.block.saved_main
    print("main activation requires_grad:", h.requires_grad)
    print("main activation grad:",
          None if h.grad is None else h.grad.norm().item())


x = torch.randn(4, 1, 64, 64)
target = torch.tensor([0, 1, 1, 0])

model = TinyUSNet()
print("\n[baseline]")
run_step(model, x, target)

print("\n[accidental detach]")
model.block.detach_main = True
run_step(model, x, target)

관찰 포인트:

  1. baseline에서는 conv1, conv2가 모두 finite gradient를 가져야 합니다.

  2. detach 실험에서는 block main branch의 parameter gradient가 None이 됩니다.

  3. identity path가 남아 있으므로 stem과 head에는 gradient가 전달됩니다.

  4. detect_anomaly()는 원인 추적용이므로 전체 학습에서 상시 사용하지 않습니다.

실습 C — 동결과 optimizer 구성 확인

model = TinyUSNet()

for p in model.stem.parameters():
    p.requires_grad_(False)

trainable = [p for p in model.parameters() if p.requires_grad]
optimizer = torch.optim.AdamW(trainable, lr=3e-4, weight_decay=1e-2)

print("all params:", sum(p.numel() for p in model.parameters()))
print("trainable params:", sum(p.numel() for p in trainable))

optimizer.zero_grad(set_to_none=True)
loss = F.cross_entropy(model(x), target)
loss.backward()

for name, p in model.named_parameters():
    if name.startswith("stem"):
        print(name, "requires_grad=", p.requires_grad, "grad=", p.grad)

stem parameter는 requires_grad=False, grad=None이어야 합니다. block과 head는 계속 학습됩니다.

선택 과제 — gradcheck

직접 만든 differentiable 연산이 있다면 double precision과 작은 입력으로 수치 미분을 비교합니다.

from torch.autograd import gradcheck

def smooth_fn(x):
    return torch.sin(x) * torch.exp(0.2 * x)

x64 = torch.randn(4, dtype=torch.float64, requires_grad=True)
ok = gradcheck(smooth_fn, (x64,), eps=1e-6, atol=1e-4)
print("gradcheck:", ok)

6. 예상 결과와 디버깅 포인트

증상 우선 확인 대표 원인
grad is None requires_grad, 그래프 연결, backward 시점 동결, detach, 사용되지 않은 branch, zero_grad 직후
gradient가 정확히 0 activation mask와 입력 분포 dead ReLU, hard threshold, mask로 모든 위치 제거
매우 작은 gradient layer별 norm의 깊이 방향 변화 포화 activation, 긴 Jacobian 곱, 과도한 loss scale 차이
NaN/Inf 처음 비정상이 발생한 연산 0으로 나눔, log 입력 오류, overflow, AMP 불안정
두 번째 backward 오류 같은 graph를 재사용했는지 첫 backward 후 graph가 해제됨
in-place 수정 오류 inplace=True, +=, view 수정 backward에 필요한 저장값이 변경됨

실전 진단 순서:

  1. loss가 finite인지 확인합니다.

  2. head에서 backbone 방향으로 parameter gradient norm을 출력합니다.

  3. None과 0을 구분합니다.

  4. 이상이 시작되는 block에만 activation retain_grad() 또는 hook을 추가합니다.

  5. detect_anomaly()로 최초 실패 연산을 찾습니다.

  6. learning rate, loss weight, normalization, AMP를 하나씩 분리해 비교합니다.

  7. gradient clipping은 폭주의 증상을 줄일 수 있지만 원인 분석을 대신하지 않습니다.

7. 복습 문제

  1. non-leaf activation의 .grad가 기본적으로 None인 이유와 확인 방법은 무엇인가?

  2. model.eval()과 torch.no_grad()의 역할 차이는 무엇인가?

  3. optimizer.zero_grad()를 호출하지 않으면 어떤 일이 일어나는가?

  4. y=x+F(x)의 residual 구조가 gradient flow에 도움이 되는 이유를 식으로 설명하라.

  5. block parameter의 grad=None이지만 그 앞 stem에는 gradient가 존재한다. 어떤 코드 실수를 의심할 수 있는가?

    정답과 해설

  6. non-leaf tensor는 메모리를 절약하기 위해 gradient를 기본 보존하지 않습니다. forward 중 해당 tensor에 retain_grad()를 호출한 뒤 backward 후 .grad를 확인합니다.

  7. model.eval()은 Dropout과 BatchNorm 같은 모듈의 동작을 평가 모드로 바꿉니다. no_grad()는 계산 그래프 기록을 끕니다. 추론에서는 보통 둘을 함께 사용합니다.

  8. 이전 step의 gradient에 새 gradient가 더해집니다. 의도한 accumulation이 아니라면 update 크기가 왜곡됩니다.

  9. ∂y/∂x = I + J_F이므로 복잡한 main branch 외에 identity를 통한 직접 gradient 경로가 존재합니다.

  10. main branch 출력에 실수로 detach()를 적용했거나, 해당 block이 실제 loss 경로에서 사용되지 않았는지 확인합니다. identity skip 때문에 stem과 head는 계속 gradient를 받을 수 있습니다.
