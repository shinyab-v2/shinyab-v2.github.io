AI 전문 개발 학습 #02 — Autograd & Gradient Flow

Computational graph, chain rule, requires_grad와 detach, residual connection의 gradient 흐름을 추적합니다.

예상 학습시간: 45~60분

여기부터 모델을 단순히 forward하는 개발자와 학습 자체를 이해하는 개발자의 차이가 생깁니다.

1. 아주 간단한 예제

x = torch.tensor(2.0, requires_grad=True)

y = x ** 2

수학적으로:

y = x²

따라서:

dy/dx = 2x

x=2이면:

dy/dx = 4

PyTorch에서는:

y.backward()

print(x.grad)

결과:

tensor(4.)

입니다.

PyTorch Autograd는 연산 과정에서 backward에 필요한 계산 그래프와 정보를 관리합니다.

2. Computational Graph

조금 더 복잡하게:

x = torch.tensor(2.0, requires_grad=True)

a = x * 3
b = a ** 2
y = b + 1

forward:

x
│
×3
│
a
│
square
│
b
│
+1
│
y

수학적으로:

a = 3x
b = a²
y = b + 1

따라서:

dy/db = 1
db/da = 2a
da/dx = 3

Chain rule:

dy/dx
=
dy/db × db/da × da/dx

x=2이면 a=6이므로:

1 × 12 × 3
= 36

3. 실제 Neural Network에서는

x
↓
Conv1
↓
ReLU
↓
Conv2
↓
ReLU
↓
Classifier
↓
Loss

Backward는 반대 방향입니다.

Loss
 ↑
Classifier
 ↑
Conv2
 ↑
Conv1

각 parameter에 대해:

∂Loss / ∂Weight

를 계산합니다.

optimizer는 이 gradient를 사용합니다.

단순화하면:

Wnew = Wold - learning_rate × gradient

입니다.

4. requires_grad

for p in model.parameters():
    print(p.requires_grad)

대부분:

True

입니다.

Fine-tuning에서 자주 하는:

for p in model.backbone.parameters():
    p.requires_grad = False

는 단순히

parameter가 update되지 않는다.

보다 조금 더 정확하게는,

해당 parameter에 대해 autograd가 gradient를 기록하도록 요구하지 않는다.

는 의미입니다.

PyTorch에는 module 전체 parameter의 requires_grad를 변경하는 requires_grad_()도 제공됩니다.

5. detach()는 무엇인가?

예:

feature = backbone(x)

feature2 = feature.detach()

output = head(feature2)

graph 관점:

backbone
   ↓
 feature
   X ← gradient 차단
 feature2
   ↓
 head

따라서 head는 학습되지만 해당 경로를 통한 gradient가 backbone까지 전달되지 않습니다.

이것은 매우 중요합니다.

6. Residual Connection

ResNet의 핵심 구조:

y = F(x) + x

입니다.

미분하면:

dy/dx = dF/dx + 1

여기서 +1이 중요합니다.

gradient가 복잡한 F(x)를 통하지 않고도 identity path를 통해 전달될 수 있습니다.

x ─────────────────┐
│                  │
Conv                │
↓                   │
ReLU                │
↓                   │
Conv                │
│                   │
└──────── + ←───────┘
           │
           y

이것이 deep network 학습을 훨씬 쉽게 만든 핵심 아이디어 중 하나입니다.

7. Gradient Vanishing

만약 gradient가 각 layer에서:

0.1

배씩 줄어든다고 가정하면 10 layer를 통과하면:

0.1^10

입니다.

즉:

0.0000000001

수준이 됩니다.

앞쪽 layer는 사실상 학습되지 않을 수 있습니다.

이를 gradient vanishing이라고 합니다.

반대로 계속 커지면:

gradient explosion

입니다.

8. 실제 Gradient 확인

다음 코드는 앞으로 모델 debugging에 매우 중요합니다.

loss.backward()

for name, param in model.named_parameters():
    if param.grad is not None:
        print(
            name,
            param.grad.abs().mean().item()
        )

예:

encoder.conv1.weight  0.000001
encoder.conv2.weight  0.000003
encoder.conv3.weight  0.0042
head.weight           0.0821

이런 결과가 계속 나온다면:

앞쪽 encoder gradient가 지나치게 작다.

라는 의심을 할 수 있습니다.

9. Gradient Hook

Tensor에 hook을 걸 수도 있습니다.

def print_grad(grad):
    print(grad.abs().mean())

feature.register_hook(print_grad)

backward 때 feature gradient를 볼 수 있습니다.

PyTorch는 module/tensor hook을 통해 activation이나 gradient를 검사하는 기능을 제공하며, 현재 공식 튜토리얼에서도 gradient visualization/debugging 용도로 설명합니다.

10. 실전 디버깅 사고법

예를 들어 ultrasound detection model에서:

Loss가 감소하지 않는다.

라고 합시다.

learning rate부터 무작정 변경하면 안 됩니다.

다음 순서로 확인합니다.

① Input 정상?
        ↓
② Label 정상?
        ↓
③ Forward output 정상?
        ↓
④ Loss 계산 정상?
        ↓
⑤ Gradient 생성?
        ↓
⑥ 각 layer까지 gradient 전달?
        ↓
⑦ optimizer가 parameter update?

예:

for name, p in model.named_parameters():
    if p.grad is None:
        print("NO GRAD:", name)

이것만으로도 상당히 많은 학습 문제를 찾을 수 있습니다.
