Residual Block 수정: Dilation·Stride·Projection

작은 병변의 위치 정보는 덜 잃으면서 더 넓은 문맥을 보기 위해 stride·dilation·projection을 어떻게 조합해야 하는지 Tensor shape와 receptive field 관점에서 해부합니다.

그림으로 이해하는 Stride · Dilation · Receptive Field

Stride(스트라이드)는 convolution filter의 이동 간격, Dilation(팽창 계수)은 filter 내부 원소의 샘플링 간격, Receptive Field(RF, 수용 영역)는 출력의 한 위치가 이론적으로 참조할 수 있는 입력 영역입니다. 서로 다른 개념이며, 모두 CNN(Convolutional Neural Network, 합성곱 신경망)의 공간 정보 처리에 영향을 줍니다.

Stride 예시: 입력 7×7, kernel=3, padding=1, dilation=1일 때 stride=1은 7×7, stride=2는 4×4를 출력합니다. stride가 2배라고 출력이 언제나 정확히 절반인 것은 아니며 floor 연산과 padding을 고려해야 합니다.

Dilation 예시: 3×3 kernel에서 dilation=2는 5×5의 외곽 범위 안에 간격을 두고 배치된 9개 위치를 샘플링합니다. 5×5의 25개 위치를 모두 읽는 일반 convolution과 다릅니다. 동일한 3×3 weight 개수로 넓은 문맥을 살필 수 있지만, 인접 픽셀을 건너뛰는 gridding artifact(격자 형태의 정보 누락)가 발생할 수 있습니다.

Receptive Field 예시: 3×3 Conv를 stride=1, dilation=1로 두 번 연결하면 첫 층의 이론적 RF는 3×3, 두 번째 층은 5×5입니다. 시작값 r₀=1, j₀=1에서 rₗ=rₗ₋₁+(k_eff−1)jₗ₋₁, jₗ=jₗ₋₁×strideₗ로 누적합니다. 이는 이론적 RF이며, 실제 예측에 강하게 기여하는 Effective Receptive Field(유효 수용 영역)는 더 좁거나 불균일할 수 있습니다.

초음파 예시: 원본 640×640 영상의 16×16 pixel 병변은 stride=8 feature map에서 대략 2×2 cell 간격에 대응하고 stride=32에서는 0.5×0.5 cell 간격에 해당합니다. 이것이 병변 정보가 반드시 사라진다는 뜻은 아니지만 작은 병변 localization이 어려워질 수 있다는 신호입니다. 따라서 stride 제거·dilation 도입·P2/P3 high-resolution feature 활용을 실험하고 sensitivity, FP/image, VRAM과 latency를 함께 비교합니다.

P2·P3는 왜 stride 4·8인가? Stride=1이 더 좋지 않을까?

Pyramid Level(피라미드 단계)을 의미하는 P2, P3, P4, P5는 일반적인 FPN(Feature Pyramid Network, 특징 피라미드 네트워크) 계열에서 사용하는 관례적 명칭입니다. 숫자가 1 증가할 때 누적 stride는 대개 2배가 됩니다. 4씩 더하는 규칙이 아닙니다. 모델에 따라 level 정의가 다를 수 있으므로 실제 코드에서 stride를 확인해야 합니다.

Stride=1이 공간 해상도는 가장 높습니다. 하지만 같은 channel 수를 유지하면 640×640 feature map은 160×160(P2, stride 4)보다 공간 위치와 activation 저장량이 16배입니다. 64 channel, FP32, batch=1에서 각각 약 100 MiB 대 6.25 MiB입니다(단일 activation Tensor만 계산).

또한 높은 해상도만으로 충분한 병변 인식 능력이 보장되지는 않습니다. 얕은 층은 경계·텍스처 등 위치 정보를 풍부하게 담는 반면, 깊은 층은 넓은 문맥과 의미 정보를 학습합니다. FPN은 이 두 성질을 결합하려는 구조입니다.

16×16 px 초음파 병변 예시: 원본 영상에서 16×16 px로 가정한 병변은 P2(stride 4)에서 약 4×4, P3(stride 8)에서 약 2×2, P5(stride 32)에서 0.5×0.5 cell 간격에 대응합니다. 반쪽 cell이 실제 존재하는 것은 아니며, 병변 폭이 feature cell 중심 간격보다 작다는 뜻입니다. 이는 공간 축척에 관한 근사이지 모델 내부에서 병변이 실제로 해당 수의 cell에만 나타난다는 보장은 아닙니다.

실험 제안: baseline P3/P4/P5와 P2 추가 모델을 비교하고, small-lesion sensitivity, FP/image(이미지당 거짓 양성 검출 수), VRAM(Video Random Access Memory, GPU 메모리), latency(추론 지연시간)를 동시에 측정합니다. 필요하면 stride를 줄이거나 dilation을 도입하되 계산 비용과 성능을 함께 확인합니다.

1. Conv2d 출력 크기

한 축의 입력 크기를 H_in이라 할 때 출력은 다음과 같습니다.

H_out = floor((H_in + 2p - d(k-1) - 1) / s + 1)

k는 kernel, s는 stride, p는 padding, d는 dilation입니다. 입력 64, kernel 3, padding 1, dilation 1이면 stride 1에서 64, stride 2에서 32가 됩니다. kernel 3, dilation 2에서 공간 크기를 유지하려면 일반적으로 padding 2를 사용합니다.

2. Dilation과 Receptive Field

Dilation은 parameter 수를 늘리지 않고 커널이 보는 nominal 범위를 넓힙니다.

k_eff = d * (k - 1) + 1

3x3, d=1 -> effective 3x3
3x3, d=2 -> effective 5x5
3x3, d=3 -> effective 7x7
중요: 3×3 dilation=2가 5×5의 모든 25개 위치를 읽는 것은 아닙니다. 5×5 범위 안에서 간격을 둔 9개 위치만 sampling합니다. 따라서 weight parameter 수는 일반 3×3과 같습니다.

레이어를 통과할 때 입력 좌표 간격 j와 receptive field r은 다음처럼 누적할 수 있습니다.

j_l = j_(l-1) * stride_l
r_l = r_(l-1) + (k_eff_l - 1) * j_(l-1)
구성최종 r최종 jump출력 해상도
Conv3 s=2 → Conv3 s=172절반
Conv3 d=2 → Conv3 d=291유지

3. Residual addition의 Shape 계약

Residual block은 y = F(x) + P(x)를 계산합니다. 덧셈 직전 main path와 identity/projection path의 N, C, H, W가 의도대로 같아야 합니다.

  • channel·공간 크기 동일 → nn.Identity()
  • channel만 다름 → 1×1 Conv, stride 1
  • channel과 공간 크기 모두 변경 → 1×1 Conv, main path와 같은 stride
흔한 오류: main path의 stride를 2→1로 바꾸고 projection stride를 2로 그대로 두면 main과 skip의 H/W가 달라져 residual addition이 실패합니다.

4. 수정 가능한 Residual Block

import torch
import torch.nn as nn
import torch.nn.functional as F

class ResidualBlock(nn.Module):
    def __init__(self, in_channels, out_channels,
                 stride=1, dilation=1):
        super().__init__()
        padding = dilation

        self.conv1 = nn.Conv2d(
            in_channels, out_channels, 3,
            stride=stride, padding=padding,
            dilation=dilation, bias=False)
        self.bn1 = nn.BatchNorm2d(out_channels)
        self.conv2 = nn.Conv2d(
            out_channels, out_channels, 3,
            stride=1, padding=padding,
            dilation=dilation, bias=False)
        self.bn2 = nn.BatchNorm2d(out_channels)

        needs_projection = stride != 1 or in_channels != out_channels
        self.projection = (
            nn.Sequential(
                nn.Conv2d(in_channels, out_channels, 1,
                          stride=stride, bias=False),
                nn.BatchNorm2d(out_channels))
            if needs_projection else nn.Identity())

    def forward(self, x):
        identity = self.projection(x)
        out = F.relu(self.bn1(self.conv1(x)), inplace=False)
        out = self.bn2(self.conv2(out))
        if out.shape != identity.shape:
            raise RuntimeError(
                f"Residual shape mismatch: main={out.shape}, skip={identity.shape}")
        return F.relu(out + identity, inplace=False)

두 변형을 직접 비교

x = torch.randn(2, 16, 64, 64)

stride_block = ResidualBlock(16, 32, stride=2, dilation=1)
dilated_block = ResidualBlock(16, 32, stride=1, dilation=2)

print(stride_block(x).shape)   # [2, 32, 32, 32]
print(dilated_block(x).shape)  # [2, 32, 64, 64]

두 block의 convolution weight shape는 같습니다. stride·padding·dilation은 weight Tensor의 차원을 바꾸지 않기 때문입니다. 그러나 dilated block은 더 큰 feature map을 유지하므로 activation memory와 이후 연산량이 크게 증가합니다.

5. 설계 Trade-off

설계장점위험
Stride 2 유지메모리·연산량 감소, 빠른 문맥 압축작은 병변·얇은 경계 손실 가능
Stride 1 + Dilation 2공간 해상도 유지, nominal RF 확대activation/MAC 증가, gridding 가능성
혼합 dilation [1,2,3] 또는 [1,2,4]local/context 균형, sampling hole 완화설계 복잡도 증가, 작은 feature map에서 padding 비중 증가

Pretrained checkpoint 호환성

stride 2→1, dilation 1→2, padding 1→2는 일반적으로 convolution weight shape를 유지하므로 기존 weight를 로드할 수 있습니다. 하지만 계산 위치와 activation 분포가 달라지므로 shape 호환이 의미 호환을 보장하지 않습니다.

Stride·Dilation 구조 변경 후 Pretrained Weight는 재사용할 수 있을까?

결론: stride=2 → 1, dilation=1 → 2, padding=1 → 2처럼 in_channels, out_channels, kernel_size, groups가 유지되면 보통 convolution weight의 shape는 변하지 않습니다. 기존 weight를 초기값으로 로드한 뒤 Fine-tuning(사전 학습된 모델을 새로운 데이터·목적에 맞게 추가 학습)으로 적응시킬 수 있습니다. 하지만 로드 가능 ≠ 같은 feature 출력 ≠ 성능 보장입니다.

어떤 가중치를 재사용할까?

구성 요소시작 전략주의점
변경 없는 초기 BackbonePretrained Weight 재사용낮은 학습률 또는 초기 freeze 검토
Stride·Dilation만 변경한 ConvWeight 복사 후 Fine-tuningsampling 위치가 바뀌므로 feature 의미 재적응
Batch Normalization(BN)학습/통계 재보정 검토running_mean·running_var가 새 activation 분포에 맞지 않을 수 있음
새로 추가한 P2/FPN대응 weight 없으면 초기화feature 채널 수와 lateral connection 확인
기존 Headshape가 맞으면 재사용 검토입력 feature 분포와 anchor/stride 설정 확인

최소 실행 예시: Conv Weight 복사

import torch
from torch import nn

old = nn.Conv2d(64, 128, 3, stride=2, padding=1, dilation=1)
new = nn.Conv2d(64, 128, 3, stride=1, padding=2, dilation=2)
new.load_state_dict(old.state_dict())  # weight, bias shape 동일
x = torch.randn(1, 64, 64, 64)
assert old(x).shape == (1, 128, 32, 32)
assert new(x).shape == (1, 128, 64, 64)
assert torch.equal(old.weight, new.weight)
print('weights reused, feature geometry changed')

이 코드는 Conv 하나의 재사용 가능성을 확인하는 예제입니다. 전체 ResNet/Detection Model에서 stage stride를 바꾸면 이후 stage의 해상도와 FPN lateral connection, projection/skip path, head의 stride 설정까지 함께 검증해야 합니다.

권장 실험 순서

  1. Baseline과 변경 모델의 state_dict key·shape 일치 여부를 검사합니다. strict=False가 shape mismatch까지 자동 해결하지는 않습니다.
  2. 변경한 stage와 downstream layer를 학습 가능하게 두고, unchanged early backbone에는 상대적으로 작은 learning rate를 검토합니다.
  3. BN 통계, feature activation, gradient, 실제 parameter update를 확인합니다.
  4. 같은 patient-level validation split에서 작은 병변 sensitivity, FP/image, latency, VRAM을 비교합니다.
  5. 성능 저하가 지속되면 기존 stride 유지, P2 추가, dilation만 변경 등 단일 변수 ablation으로 원인을 분리합니다.
중요: Fine-tuning은 변경된 구조에 적응할 가능성을 제공하지만, 원래의 sampling 정보나 학습 데이터에 없는 특징을 자동 복원하지는 않습니다. 특히 초음파 작은 병변은 위치·경계·speckle 특성이 중요하므로 성능 회복 여부를 실제 데이터로 검증해야 합니다.

변경 전·후 Flow에서 어떤 Weight를 학습할까?

실무적 출발점: Stride/Dilation 변경 이전 stage는 pretrained weight를 유지하고 초기에는 freeze할 수 있습니다. 변경 지점과 그 영향을 받는 이후 stage·neck·head는 호환되는 pretrained weight를 초기값으로 로드한 뒤 Fine-tuning하는 전략이 합리적입니다. 이후 모든 weight를 처음부터 초기화하는 Training from Scratch가 기본값은 아닙니다.

구간초기화학습 여부
변경 전 Backbone기존 weight초기 freeze 가능; 추후 낮은 LR로 unfreeze 검토
변경된 Conv/Stageshape 호환 weight 재사용Fine-tuning 권장
변경 후 Stage/Neck/Head호환 weight 재사용새 feature 분포에 적응하도록 Fine-tuning
신규 layer 또는 shape 불일치새 초기화 또는 명시적 weight 변환학습 필요

용어: Freeze는 parameter update를 중단하는 것, Fine-tuning은 기존 pretrained weight에서 시작해 추가 학습하는 것, Training from Scratch는 weight를 새로 초기화하는 것입니다. Batch Normalization(BN)은 requires_grad=False만으로 running statistics 갱신이 멈추지 않으므로 eval() 여부까지 의도적으로 관리해야 합니다.

예외: Skip connection, FPN lateral branch 등으로 변경 이전·이후 feature가 합쳐질 수 있으므로 단순한 순차 흐름만 가정하지 않습니다. Freeze 범위와 LR는 검증 데이터의 small-lesion sensitivity, FP/image, latency를 기준으로 ablation 비교해야 합니다.

6. 직접 실행 실습

A. 출력 shape 공식 검증

from math import floor

def conv2d_output_size(size, kernel_size=3,
                       stride=1, padding=0, dilation=1):
    return floor((size + 2*padding
                  - dilation*(kernel_size-1) - 1)
                 / stride + 1)

cases = [
    dict(stride=1, padding=1, dilation=1),
    dict(stride=2, padding=1, dilation=1),
    dict(stride=1, padding=2, dilation=2),
    dict(stride=1, padding=3, dilation=3),
]
for case in cases:
    print(case, conv2d_output_size(64, **case))

B. parameter와 activation 비교

def count_params(m):
    return sum(p.numel() for p in m.parameters())

print(count_params(stride_block))
print(count_params(dilated_block))

with torch.no_grad():
    a = stride_block(x)
    b = dilated_block(x)
    print(a.numel(), b.numel())  # high-res activation은 4배

C. Gradient 확인

for model in [stride_block, dilated_block]:
    model.train()
    y = model(x)
    loss = y.square().mean()
    loss.backward()
    for name, p in model.named_parameters():
        assert p.grad is not None, name

7. 초음파 AI에 적용할 때

작은 breast lesion, 얇은 경계, B-line처럼 위치 정보가 중요한 target은 early downsampling에서 사라질 수 있습니다. 하지만 모든 stage의 stride를 제거하면 memory/latency가 급증합니다. 따라서 baseline 대비 특정 stage 하나만 stride→dilation으로 바꾸고 lesion size별 sensitivity, localization error, GPU memory, latency를 함께 비교하는 실험이 현실적입니다.

추천 실험: Baseline / Stage3만 dilation / Stage3+4 dilation 세 모델을 동일 seed·augmentation·optimizer로 비교하고, 전체 성능뿐 아니라 작은 병변 subgroup을 별도로 평가합니다.

8. 복습 문제

  1. 3×3, dilation=2의 effective kernel은? 5×5.
  2. stride 2가 jump에 미치는 영향은? 인접 feature 중심의 입력 좌표 간격을 두 배로 만듭니다.
  3. main stride를 2→1로 바꿀 때 projection에서 무엇을 확인해야 하나? projection stride도 같은 spatial contract를 유지하도록 수정해야 합니다.
  4. dilation이 parameter 수를 늘리지 않는 이유는? weight element 수는 여전히 3×3×Cin×Cout이기 때문입니다.
  5. shape가 같은 pretrained weight를 로드했다고 동일 의미인가? 아닙니다. sampling 위치와 activation distribution이 바뀝니다.
