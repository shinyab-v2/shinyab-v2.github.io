2026.09.11#10Loss Design

Loss는 점수가 아니라
Gradient를 설계하는 함수다

BCE·Focal·Dice·IoU loss를 “값이 얼마나 작은가”가 아니라 어떤 sample/pixel에 얼마만큼 gradient를 배분하는가라는 관점에서 비교합니다.

1. BCE부터 시작

L = -[ y log(p) + (1-y) log(1-p) ]

binary classification의 기본입니다. 하지만 detection처럼 background가 압도적으로 많으면 쉬운 negative들이 loss를 지배할 수 있습니다.

2. Focal Loss

FL(p_t) = - alpha_t (1 - p_t)^gamma log(p_t)

잘 맞힌 sample은 (1-p_t)^gamma가 작아져 contribution이 감소합니다. gamma=0이면 weighted CE/BCE 형태로 돌아갑니다. gamma가 커질수록 hard example에 상대적으로 더 집중하지만 너무 크면 학습 가능한 easy/medium sample의 gradient까지 지나치게 줄일 수 있습니다.

3. Dice Loss

Dice = (2 * sum(p*y) + eps) / (sum(p) + sum(y) + eps)
Loss = 1 - Dice

segmentation에서 foreground가 작을 때 pixel-wise BCE보다 region overlap을 직접 최적화하는 장점이 있습니다. 다만 calibration과 local pixel error를 BCE처럼 직접 다루지는 않으므로 BCE+Dice 조합이 흔합니다.

4. IoU 계열

Bounding box regression에서는 좌표별 L1만으로는 box overlap 품질을 직접 반영하기 어렵습니다. IoU/GIoU/DIoU/CIoU 계열은 box geometry와 overlap을 목적 함수에 포함합니다.

5. Loss scale을 그대로 비교하면 안 되는 이유

loss 0.2가 loss 1.0보다 항상 “좋다”는 의미가 아닙니다. 정의와 reduction, class weighting이 다르면 scale 자체가 다릅니다. 중요한 것은 validation metric과 gradient behavior입니다.

6. Multi-task loss

L_total = lambda_cls * L_cls \
        + lambda_box * L_box \
        + lambda_seg * L_seg

lambda는 단순 숫자가 아니라 각 task gradient가 shared backbone에 미치는 영향력을 조절합니다. 한 loss의 scale이 지나치게 크면 다른 task 학습을 압도할 수 있습니다.

7. Gradient를 직접 확인

optimizer.zero_grad()
loss_cls.backward(retain_graph=True)
cls_norm = model.backbone.layer3[0].conv1.weight.grad.norm().item()

optimizer.zero_grad()
loss_box.backward(retain_graph=True)
box_norm = model.backbone.layer3[0].conv1.weight.grad.norm().item()
print(cls_norm, box_norm)

이렇게 shared parameter에 각 loss가 만드는 gradient 크기를 비교하면 multi-task imbalance를 더 직접적으로 볼 수 있습니다.

8. Ultrasound 예시

작은 lesion segmentation에서는 foreground pixel이 극히 적어 BCE만 사용하면 background를 잘 맞히는 방향으로 최적화되기 쉽습니다. Dice/Focal을 함께 검토하되 전체 Dice뿐 아니라 lesion-level sensitivity, false positive, 작은 병변 subgroup을 같이 봐야 합니다.
