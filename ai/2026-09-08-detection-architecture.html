2026.09.08#07Detection Architecture

Detection Architecture
Backbone → Neck → Head

Detection 모델을 단순히 “박스를 찾는 네트워크”로 보지 않고, 서로 다른 해상도의 feature를 어떻게 만들고 합치며 최종 box/class 예측으로 변환하는지 Tensor 관점에서 추적합니다.

1. Detection을 Tensor pipeline으로 보기

Classification은 보통 마지막에 하나의 class vector를 만들지만 detection은 공간 정보를 끝까지 유지해야 합니다. 그래서 backbone의 여러 stage에서 feature를 꺼내고, neck이 서로 다른 해상도를 융합한 뒤, head가 각 위치에서 box와 class를 예측합니다.

Backboneedge → texture → semantic feature
Neckmulti-scale feature fusion
Headbox / class / objectness prediction

2. 왜 FPN이 필요한가?

깊은 feature는 의미 정보가 풍부하지만 spatial resolution이 낮습니다. 반대로 얕은 feature는 위치 정보가 좋지만 semantic abstraction이 약합니다. FPN은 두 정보를 결합합니다.

Input: 640×640
C3: [B, 256, 80, 80]
C4: [B, 512, 40, 40]
C5: [B,1024, 20, 20]

Top-down:
P5 = lateral(C5)
P4 = lateral(C4) + upsample(P5)
P3 = lateral(C3) + upsample(P4)

여기서 upsample만 한다고 정보가 새로 생기는 것은 아닙니다. 깊은 semantic feature를 높은 해상도의 lateral feature와 합쳐 “무엇인지”와 “어디 있는지”를 동시에 보존하는 것이 핵심입니다.

3. 작은 병변과 feature scale

초음파에서 작은 breast lesion이나 B-line은 early downsampling에서 쉽게 사라질 수 있습니다. 예를 들어 640 입력에서 stride 8인 P3는 한 feature cell이 원본의 약 8×8 영역에 대응하지만 stride 32인 P5는 약 32×32 영역에 대응합니다.

FeatureStride해상도주요 역할
P3880×80작은 객체·경계
P41640×40중간 크기
P53220×20큰 객체·문맥

4. Anchor-based vs Anchor-free

Anchor-based는 사전에 정한 box prior를 각 위치에 배치하고 offset을 예측합니다. Anchor-free는 중심점·거리·분포 등을 직접 예측합니다. 최근 detector는 anchor-free 설계가 많지만, 핵심은 둘 다 spatial feature 위에서 box geometry를 학습한다는 점입니다.

5. PyTorch mini FPN

class MiniFPN(nn.Module):
    def __init__(self, c3=256, c4=512, c5=1024, out=256):
        super().__init__()
        self.l3 = nn.Conv2d(c3, out, 1)
        self.l4 = nn.Conv2d(c4, out, 1)
        self.l5 = nn.Conv2d(c5, out, 1)

    def forward(self, c3, c4, c5):
        p5 = self.l5(c5)
        p4 = self.l4(c4) + F.interpolate(p5, size=c4.shape[-2:], mode='nearest')
        p3 = self.l3(c3) + F.interpolate(p4, size=c3.shape[-2:], mode='nearest')
        return p3, p4, p5

중요한 shape contract는 channel을 256으로 맞춘 후 spatial size만 upsample하여 더하는 것입니다. channel 또는 H/W가 다르면 element-wise add가 불가능합니다.

6. Architecture trade-off

  • P2 같은 더 높은 해상도 feature를 추가하면 작은 병변 sensitivity가 좋아질 가능성이 있지만 메모리와 연산량이 크게 증가합니다.
  • FPN channel 256→128은 연산량과 memory를 줄이지만 표현 능력을 줄일 수 있습니다.
  • BiFPN/PAN처럼 양방향 융합을 쓰면 feature interaction은 늘지만 latency와 구현 복잡도가 증가합니다.

7. Ultrasound 실전 실험

작은 lesion dataset이라면 baseline P3/P4/P5와 P2/P3/P4/P5를 비교하고, 전체 mAP만 보지 말고 lesion size별 sensitivity와 false positive를 같이 비교합니다. 병변 크기를 픽셀/화면 비율로 나눠 작은 subgroup을 별도로 평가하는 것이 중요합니다.

8. 복습 문제

  1. FPN이 lateral connection을 쓰는 이유는? 깊은 semantic 정보와 얕은 spatial detail을 결합하기 위해서.
  2. P3가 P5보다 작은 병변에 유리한 이유는? spatial resolution이 더 높기 때문.
  3. 1×1 Conv의 역할은? 주로 channel projection/alignment.
  4. Upsampling만으로 semantic 정보가 생기는가? 아니다.
  5. 작은 병변 성능을 높이기 위해 모든 downsampling을 제거해도 되는가? 연산량·memory·context trade-off 때문에 실험적으로 판단해야 한다.
