Distributed Training & DDP

Data Parallelism과 DistributedDataParallel의 데이터·gradient 흐름

1. 오늘의 목표

Data Parallelism과 DistributedDataParallel의 데이터·gradient 흐름. 이번 회차는 약 40~60분을 기준으로 하며, 개념 설명 뒤 실제 코드와 수치 확인까지 진행합니다.

DDP

Full name / 의미: DistributedDataParallel

각 process/GPU가 모델 replica를 갖고 gradient를 동기화하는 PyTorch 분산 학습 방식

All-Reduce

Full name / 의미: Collective reduction operation

여러 process의 gradient를 합산/평균하여 동일한 parameter update를 가능하게 하는 통신 연산

DistributedSampler

Full name / 의미: 분산 샘플러

각 process가 서로 다른 dataset subset을 받도록 index를 분배

5. 구체적인 Ultrasound AI 예시

2 GPU에서 global batch=16이면 GPU당 local batch=8로 처리한 뒤 gradient를 all-reduce합니다.

6. 실제 코드에서 확인

model = torch.nn.parallel.DistributedDataParallel(model,
        device_ids=[local_rank])
sampler = DistributedSampler(dataset, shuffle=True)
loader = DataLoader(dataset, batch_size=8, sampler=sampler)
for epoch in range(E):
    sampler.set_epoch(epoch)

코드를 그대로 실행하는 것보다 각 줄에서 입력/출력 Tensor, parameter 등록 여부, gradient 발생 여부, device와 dtype을 함께 출력해 보는 것이 핵심입니다.

7. 설계 Trade-off

성능 향상이 항상 좋은 변경은 아닙니다. accuracy/sensitivity뿐 아니라 GPU memory, throughput, latency, reproducibility, 작은 병변 subgroup 성능을 함께 기록합니다. 변경 전 baseline을 남기고 한 번에 하나의 주요 변수를 바꿉니다.

8. Debugging 실습

  1. 입력 batch의 shape·dtype·min/max를 기록합니다.
  2. 핵심 layer의 output shape를 hook으로 확인합니다.
  3. loss가 finite인지 확인합니다.
  4. backward 후 grad=None, NaN/Inf, grad norm을 확인합니다.
  5. optimizer.step() 전후 실제 parameter가 변했는지 확인합니다.
