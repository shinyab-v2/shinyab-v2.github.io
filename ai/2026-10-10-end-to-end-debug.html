1. 오늘의 목표

Data→Tensor→Forward→Loss→Gradient→Update→Metric 전체를 하나의 진단 절차로 통합. 이번 회차는 약 40~60분을 기준으로 하며, 개념 설명 뒤 실제 코드와 수치 확인까지 진행합니다.

Sanity Check

Full name / 의미: 기본 건전성 검사

복잡한 실험 전에 pipeline이 최소한 논리적으로 작동하는지 확인

Overfit One Batch

Full name / 의미: 단일 batch 과적합 테스트

작은 batch를 반복 학습해 모델·loss·optimizer가 실제로 학습 가능한지 확인하는 진단법

Parameter Update Ratio

Full name / 의미: 파라미터 업데이트 비율

optimizer step 전후 parameter 변화량을 parameter 크기에 상대적으로 비교한 값

5. 구체적인 Ultrasound AI 예시

training loss가 고정되어 있으면 architecture를 바꾸기 전에 8개 sample 한 batch를 반복해 거의 외울 수 있는지 확인합니다. 이것도 실패하면 데이터/label/loss/gradient/update 경로를 먼저 의심합니다.

6. 실제 코드에서 확인

before={n:p.detach().clone() for n,p in model.named_parameters()}
loss.backward(); optimizer.step()
for n,p in model.named_parameters():
    delta=(p.detach()-before[n]).norm()
    ratio=delta/(before[n].norm()+1e-12)
    print(n, float(ratio))

코드를 그대로 실행하는 것보다 각 줄에서 입력/출력 Tensor, parameter 등록 여부, gradient 발생 여부, device와 dtype을 함께 출력해 보는 것이 핵심입니다.

7. 설계 Trade-off

성능 향상이 항상 좋은 변경은 아닙니다. accuracy/sensitivity뿐 아니라 GPU memory, throughput, latency, reproducibility, 작은 병변 subgroup 성능을 함께 기록합니다. 변경 전 baseline을 남기고 한 번에 하나의 주요 변수를 바꿉니다.

8. Debugging 실습

  1. 입력 batch의 shape·dtype·min/max를 기록합니다.
  2. 핵심 layer의 output shape를 hook으로 확인합니다.
  3. loss가 finite인지 확인합니다.
  4. backward 후 grad=None, NaN/Inf, grad norm을 확인합니다.
  5. optimizer.step() 전후 실제 parameter가 변했는지 확인합니다.
