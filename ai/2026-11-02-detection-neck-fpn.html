Modern Detection Neck: FPN·PANet·BiFPN 다중 스케일 융합

Backbone의 고수준 의미론(Semantics)과 저수준 공간 해상도(Localization)를 결합하는 Neck 구조의 진화(FPN → PANet → BiFPN)를 수식과 텐서 흐름으로 해부하고, 초음파 미세 병변 보존을 위한 P2 피라미드 설계 전략을 다룹니다.

💡 Senior AI Engineer의 시각
객체 검출(Object Detection) 모델에서 Backbone(ResNet, ConvNeXt 등)만으로는 작은 객체를 잡을 수 없습니다. 고해상도 하위 레이어는 위치 정보가 풍부하지만 의미 정보(Semantics)가 약하고, 고수준 상위 레이어는 의미는 강력하지만 Stride 누적으로 작은 객체의 신호가 완전히 증발하기 때문입니다. Neck은 이 모순을 해결하는 **"공간 해상도와 의미론적 표현의 다중 스케일 교환 허브"**입니다.

1. 학습 목표 및 핵심 용어 정의

  • FPN (Feature Pyramid Networks), PANet (Path Aggregation Network), BiFPN (Bidirectional FPN)의 구조적 차이와 발전 흐름을 규명합니다.
  • $1 \times 1$ Lateral Conv, Nearest-neighbor 2배 업샘플링, $3 \times 3$ Smoothing Conv의 역할과 텐서 Shape 변화를 추적합니다.
  • 의료 초음파 영상에서 $16 \times 16$ 픽셀 미만의 작은 결절을 검출하기 위해 P2 ($S=4$) 피라미드를 추가할 때 발생하는 메모리 및 연산량 Trade-off를 수치로 증명합니다.
  • Weighted Feature Fusion(가중 특성 융합)을 파이토치 코드로 직접 구현하고 검증할 수 있습니다.

2. 왜 Detection Neck이 필수적인가?

CNN Backbone을 통과하면서 입력 영상은 점진적으로 해상도가 줄어듭니다 ($H, W \rightarrow H/2, W/2 \rightarrow \dots \rightarrow H/32, W/32$).

  • 단일 Feature Map(예: 최상위 $C_5$)만 사용할 경우: Receptive Field는 넓어 대형 객체나 전체 장기 형태는 잘 분류하지만, 공간 해상도가 너무 낮아(Stride=32) $16 \times 16$ 크기의 미세 병변은 0.5 픽셀 이하로 뭉개져 위치 회귀(Bounding Box Regression)가 불가능합니다.
  • 하위 Feature Map(예: $C_2$)만 사용할 경우: 해상도는 높지만(Stride=4), Receptive Field가 작아 국소적인 얼룩(Speckle)과 실제 종양(Lesion)을 구별할 수 있는 문맥(Semantics)이 부족하여 무수한 위양성(False Positive)이 발생합니다.

따라서 "모든 해상도 레벨에서 높은 의미론적 정보를 동시에 갖춘 피처 피라미드"를 구축해야 하며, 이것이 Neck의 본질적인 존재 이유입니다.

3. Neck 아키텍처의 진화 (FPN vs PANet vs BiFPN)

4. 피처 융합의 수학적 공식과 텐서 흐름

1) FPN의 Top-down 결합 수식

Backbone의 Stage별 출력을 $C_3, C_4, C_5$라 할 때, 최상위 레이어부터 순차적으로 계산됩니다.

$$P_5 = \text{Conv}_{3\times3}(\text{LateralConv}_{1\times1}(C_5))$$$$P_4 = \text{Conv}_{3\times3}\left(\text{LateralConv}_{1\times1}(C_4) + \text{Resize}_{2\times}(P_5)\right)$$$$P_3 = \text{Conv}_{3\times3}\left(\text{LateralConv}_{1\times1}(C_3) + \text{Resize}_{2\times}(P_4)\right)$$

여기서 $1 \times 1$ Conv는 채널을 일치시키며, 최종 $3 \times 3$ Conv는 업샘플링 보간에 의해 발생하는 에일리어싱(Aliasing) 격자 노이즈를 평활화합니다.

2) BiFPN의 Fast Normalized Fusion

단순 덧셈은 서로 다른 해상도 피처맵의 기여도를 동등하게 취급합니다. BiFPN은 Softmax의 연산 지연 없이 0~1 사이의 정규화 가중치를 부여합니다.

$$O = \sum_{i} \frac{w_i}{\epsilon + \sum_{j} w_j} \cdot I_i \quad (w_i \ge 0, \text{ ReLU로 보장})$$

5. 의료 초음파: 미세 병변(P2) 도입과 VRAM Trade-off

일반 자연영상 검출기(COCO 등)는 계산 효율을 위해 P3($S=8$)부터 P7($S=128$)까지 사용합니다. 하지만 **유방 초음파 미세석회화 및 조기 결절(Small Lesion)**은 원본 해상도에서 직경이 $10 \sim 20$ 픽셀에 불과합니다.

P2는 $160 \times 160 \times 256$ 크기의 거대한 텐서입니다. P3 대비 공간 면적이 4배이므로, P2 Head의 Anchor 수와 Activation 메모리는 급증합니다. B=8 기준 P2 활성화 텐서만으로 추가 VRAM 약 800MB가 요구되며, 미세한 Speckle 잡음에 의한 False Positive가 증가할 수 있으므로 NMS 임계값과 Focal Loss의 $\gamma$를 정밀하게 재조정해야 합니다.

6. PyTorch FPN 모듈 직접 구현

import torch
import torch.nn as nn
import torch.nn.functional as F

class FeaturePyramidNetwork(nn.Module):
    def __init__(self, in_channels_list, out_channels=256):
        """
        in_channels_list: [C2, C3, C4, C5] 채널 수 (예: [64, 128, 256, 512])
        out_channels: Neck의 통일된 피라미드 채널 수 (보통 256)
        """
        super().__init__()
        self.lateral_convs = nn.ModuleList()
        self.fpn_convs = nn.ModuleList()
        
        for in_c in in_channels_list:
            # 1x1 Lateral Conv: 채널 수 맞추기
            self.lateral_convs.append(nn.Conv2d(in_c, out_channels, kernel_size=1))
            # 3x3 Smoothing Conv: 업샘플링 에일리어싱 완화
            self.fpn_convs.append(nn.Conv2d(out_channels, out_channels, kernel_size=3, padding=1))

    def forward(self, features):
        """
        features: [C2, C3, C4, C5] 텐서 리스트 (저해상도 -> 고해상도 역순 처리)
        """
        # 1. 1x1 Lateral Conv 적용
        laterals = [lat(f) for lat, f in zip(self.lateral_convs, features)]
        
        # 2. Top-down 업샘플링 및 요소별 덧셈 (Addition)
        used_backbone_levels = len(laterals)
        for i in range(used_backbone_levels - 1, 0, -1):
            prev_shape = laterals[i - 1].shape[2:]
            laterals[i - 1] = laterals[i - 1] + F.interpolate(
                laterals[i], size=prev_shape, mode="nearest"
            )
            
        # 3. 3x3 Conv 적용하여 최종 피라미드 [P2, P3, P4, P5] 생성
        outs = [self.fpn_convs[i](laterals[i]) for i in range(used_backbone_levels)]
        return outs

# 실무 검증
if __name__ == "__main__":
    # 초음파 백본의 각 Stage 피처맵 모사 (C2: s=4, C3: s=8, C4: s=16, C5: s=32)
    c2 = torch.randn(2, 64, 160, 160)
    c3 = torch.randn(2, 128, 80, 80)
    c4 = torch.randn(2, 256, 40, 40)
    c5 = torch.randn(2, 512, 20, 20)
    
    fpn = FeaturePyramidNetwork(in_channels_list=[64, 128, 256, 512], out_channels=256)
    p2, p3, p4, p5 = fpn([c2, c3, c4, c5])
    
    print(f"P2 Shape: {p2.shape} (Stride 4  - 미세병변용)")
    print(f"P3 Shape: {p3.shape} (Stride 8)")
    print(f"P4 Shape: {p4.shape} (Stride 16)")
    print(f"P5 Shape: {p5.shape} (Stride 32 - 대형문맥용)")
    assert p2.shape == (2, 256, 160, 160)

7. 복습 퀴즈 및 상세 해설

  1. Q1. FPN에서 Lateral Connection에 $1 \times 1$ Convolution을 사용하는 주된 목적은 무엇인가?
    정답 및 해설: 서로 다른 Backbone Stage가 출력하는 다양한 채널 수($C_2=64, C_5=512$ 등)를 Neck의 단일 공통 차원($C=256$)으로 변환하여 상위 피처맵과의 요소별 덧셈이 가능하게 만들기 위함입니다.
  2. Q2. Top-down 업샘플링 후 곧바로 $3 \times 3$ Convolution을 통과시키는 이유는?
    정답 및 해설: Nearest-neighbor 보간법을 사용할 때 발생하는 계단 현상 및 격자 형태의 에일리어싱(Aliasing) 노이즈를 스무딩하고 피처를 자연스럽게 융합하기 위함입니다.
  3. Q3. PANet이 FPN에 추가한 핵심 경로는 무엇이며 왜 필요한가?
    정답 및 해설: Bottom-up 보강 경로입니다. 하위 계층에 풍부한 정밀한 위치 정보(Edge, Boundary)가 수많은 레이어를 거치며 희석되지 않고 최상위 레벨까지 단 몇 단계만에 직접 도달할 수 있도록 해줍니다.
  4. Q4. $640 \times 640$ 영상에서 직경 16 픽셀 크기의 유방 초음파 미세 종양이 Stride 32인 P5 레이어에서 소실되는 이유는?
    정답 및 해설: $16 / 32 = 0.5$ 픽셀로 축소되어 단 1개의 그리드 셀 안에도 미치지 못하므로 Bounding Box의 정밀한 회귀와 특징 보존이 불가능해집니다.
  5. Q5. BiFPN에서 단순 덧셈 대신 Fast Normalized Fusion을 도입한 이유는?
    정답 및 해설: 서로 다른 스케일의 피처맵이 가진 중요도 차이를 반영하기 위해서입니다. 무거운 Softmax 지연 없이 0~1 정규화 가중치($w_i / (\epsilon + \sum w_j)$)를 효율적으로 학습하여 추론 속도를 유지합니다.
