2026.09.14#11Training Debugging

Training Debugging
Loss → Activation → Gradient → Update

학습이 안 될 때 “loss가 안 내려간다”에서 멈추지 않고, 데이터·forward·activation·gradient·optimizer·parameter update를 단계적으로 분해해 원인을 찾는 실전 디버깅 절차를 만듭니다.

1. 먼저 “학습이 안 된다”를 정의한다

학습 실패는 여러 형태가 있습니다. loss가 완전히 고정될 수도 있고, loss는 감소하지만 validation metric이 오르지 않을 수도 있으며, 특정 class만 학습되거나 몇 step 후 NaN이 발생할 수도 있습니다. 원인 추적 전에 관찰된 증상을 정확하게 분류해야 합니다.

Optimization failure

train loss 자체가 줄지 않는다. gradient/optimizer/data path를 우선 확인합니다.

Generalization failure

train loss는 감소하지만 val 성능이 나쁘다. overfitting, split, augmentation, leakage를 확인합니다.

2. 1-batch overfit 테스트

가장 강력한 초기 테스트 중 하나는 작은 batch 하나를 반복 학습해 거의 완벽하게 맞출 수 있는지 보는 것입니다. 이것조차 실패하면 모델 capacity보다 구현 버그를 먼저 의심해야 합니다.

model.train()
x, y = next(iter(loader))
for step in range(300):
    optimizer.zero_grad(set_to_none=True)
    pred = model(x)
    loss = criterion(pred, y)
    loss.backward()
    optimizer.step()
    if step % 20 == 0:
        print(step, float(loss))
정상 기대: 데이터와 loss 조합이 적절하다면 작은 batch에서는 loss가 크게 감소해야 합니다.

3. Activation을 계측한다

forward hook을 이용해 layer별 activation의 평균, 표준편차, 최소/최대, zero ratio를 기록합니다.

def stat_hook(name):
    def hook(module, inputs, output):
        x = output.detach()
        print(name,
              'mean=', x.mean().item(),
              'std=', x.std().item(),
              'zero=', (x==0).float().mean().item(),
              'min=', x.min().item(),
              'max=', x.max().item())
    return hook

handle = model.layer2.register_forward_hook(stat_hook('layer2'))

ReLU 이후 zero ratio가 반복적으로 매우 높고 std가 거의 0이라면 dead activation을 의심할 수 있습니다. 반대로 activation이 너무 커지면 이후 loss나 gradient explosion으로 이어질 수 있습니다.

4. Gradient는 절대값 하나가 아니라 패턴으로 본다

def grad_report(model, lr=None):
    for name, p in model.named_parameters():
        if not p.requires_grad:
            continue
        if p.grad is None:
            print(name, 'NO_GRAD')
            continue
        g = p.grad.detach()
        gn = g.norm().item()
        pn = p.detach().norm().item()
        ratio = gn / (pn + 1e-12)
        msg = f'{name:45s} grad={gn:.3e} g/p={ratio:.3e}'
        if lr is not None:
            msg += f' update/p~={lr*ratio:.3e}'
        print(msg)

예를 들어 head의 g/p=1e-2인데 backbone stem이 여러 step에서 1e-8이라면 vanishing을 강하게 의심할 수 있습니다. 하지만 한 layer의 gradient가 작다는 사실만으로는 결론을 내리지 않습니다.

5. grad=None과 grad≈0을 구분한다

grad is None은 graph가 끊겼거나 parameter가 forward 경로에 사용되지 않았거나 requires_grad=False일 가능성을 먼저 봅니다. 반면 gradient tensor가 존재하지만 0에 가까우면 activation saturation, dead ReLU, loss weighting, 깊은 chain rule 효과를 봅니다.

6. NaN / Inf 진단

for name, p in model.named_parameters():
    if p.grad is not None:
        if torch.isnan(p.grad).any(): print(name, 'NaN')
        if torch.isinf(p.grad).any(): print(name, 'Inf')

NaN이 처음 발생한 지점을 찾기 위해 torch.autograd.set_detect_anomaly(True)를 임시로 사용할 수 있습니다. 다만 느리므로 항상 켜두기보다 재현용 작은 batch에서 쓰는 편이 좋습니다.

7. AMP에서 gradient를 검사할 때

scaler.scale(loss).backward()
scaler.unscale_(optimizer)   # 실제 scale로 복원 후 검사
grad_report(model)
scaler.step(optimizer)
scaler.update()

scale된 상태의 gradient를 그대로 해석하면 잘못된 결론을 내릴 수 있습니다.

8. Parameter가 실제로 움직이는지 확인

before = model.backbone.layer1[0].conv1.weight.detach().clone()
loss.backward(); optimizer.step()
after = model.backbone.layer1[0].conv1.weight.detach()
relative_change = (after-before).norm() / (before.norm()+1e-12)
print(relative_change)

gradient가 존재해도 learning rate, optimizer state, weight decay 조합 때문에 실제 update가 의미 없을 수 있습니다. 그래서 gradient 관찰 → 실제 ΔW/W 확인이 중요합니다.

9. Detection/Ultrasound 디버깅

Detection 모델에서는 head → neck → backbone stage4 → stage3 → stage2 → stem 순서로 gradient norm을 기록해보세요. 작은 lesion detector라면 classification loss는 감소하지만 box regression loss가 정체되는지, FPN/PAN의 특정 scale에만 gradient가 집중되는지도 봐야 합니다. 초음파에서는 class imbalance와 작은 병변 비율 때문에 전체 loss 감소만으로는 충분하지 않습니다.

11. 복습 문제

  1. gradient가 1e-8이면 무조건 vanishing인가? 아니다. layer별 상대 패턴과 실제 update를 함께 봐야 한다.
  2. grad=None과 0 gradient의 차이는? 전자는 경로/등록 문제 가능성이 크고, 후자는 계산은 됐지만 미분값이 거의 0인 상태다.
  3. 1-batch overfit은 무엇을 검증하는가? 데이터→forward→loss→backward→optimizer의 기본 학습 경로가 작동하는지 검증한다.
  4. AMP에서는 왜 unscale 후 검사하는가? 실제 gradient 크기를 보기 위해서다.
  5. loss가 감소해도 모델이 실패할 수 있는 이유는? 특정 class/scale만 학습되거나 generalization이 나쁠 수 있기 때문이다.
