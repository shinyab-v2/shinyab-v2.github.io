AI 전문 개발 학습 #04 — PyTorch forward 추적과 torch.fx 그래프 해부

TorchVision ResNet BasicBlock의 main·identity 경로를 추적하고 runtime hook, torch.fx Node IR, ShapeProp, graph rewrite를 이용해 모델 실행 구조를 분석·수정한다.

예상 학습 시간: 35~40분
난이도: Intermediate
사용 기술: PyTorch, torch.fx 지난 회차에서는 nn.Module의 등록 구조와 state_dict를 살펴봤습니다. 오늘은 한 단계 더 들어가서 모델의 Python forward()가 실제 연산 그래프로 어떻게 펼쳐지는지 추적합니다. 같은 모델도 세 가지 관점으로 볼 수 있습니다.

  1. print(model): 등록된 module tree

  2. Runtime hook: 특정 입력에서 실제 실행된 module과 Tensor shape

  3. torch.fx: module 호출뿐 아니라 덧셈, 함수 호출, Tensor method까지 포함한 편집 가능한 그래프

1. 학습 목표

오늘 학습을 마치면 다음을 할 수 있어야 합니다.

  • TorchVision ResNet BasicBlock의 forward를 줄 단위로 추적한다.

  • residual main path와 identity path의 shape 조건을 설명한다.

  • module tree, runtime execution trace, FX graph의 차이를 구분한다.

  • torch.fx.symbolic_trace()가 Proxy를 이용해 그래프를 만드는 원리를 이해한다.

  • FX node의 op, target, args, kwargs, users를 읽는다.

  • ShapeProp으로 각 node의 Tensor shape와 dtype을 주석 처리한다.

  • FX graph에서 F.relu를 F.silu로 교체하고 수정된 코드를 재생성한다.

  • data-dependent control flow가 symbolic tracing에 실패하는 이유를 진단한다.

2. 핵심 이론

2.1 Module tree는 실행 그래프가 아니다

다음 모델을 출력하면 convolution과 BatchNorm 같은 등록된 submodule을 볼 수 있습니다.

print(model)

그러나 module tree에는 다음 연산이 보이지 않을 수 있습니다.

  • out + identity 같은 Tensor 덧셈

  • torch.flatten(x, 1)

  • F.relu(x)와 같은 functional API

  • indexing, reshape, transpose 같은 Tensor method

  • if, for에 의해 결정되는 실행 순서 즉, print(model)은 어떤 부품이 등록됐는지 보여주지만 부품이 어떤 순서와 연결로 실행되는지 완전히 보여주지는 않습니다.

2.2 TorchVision BasicBlock 해부

TorchVision ResNet의 BasicBlock forward는 개념적으로 다음 구조입니다.

def forward(self, x):
    identity = x

    out = self.conv1(x)
    out = self.bn1(out)
    out = self.relu(out)

    out = self.conv2(out)
    out = self.bn2(out)

    if self.downsample is not None:
        identity = self.downsample(x)

    out += identity
    out = self.relu(out)

    return out

줄 단위로 해석하면 다음과 같습니다.

identity = x

입력 Tensor 객체의 별도 복사본을 만드는 것이 아닙니다. 같은 Tensor를 가리키는 reference를 저장합니다. 이후 identity는 skip connection을 통해 main path의 출력에 더해집니다.

conv1 → bn1 → relu

첫 번째 convolution은 feature를 변환하며, block이 downsampling을 담당하는 경우 stride=2가 적용될 수 있습니다. BatchNorm은 channel별 분포를 정규화하고 ReLU가 비선형성을 추가합니다.

conv2 → bn2

두 번째 convolution 뒤에는 덧셈 전에 activation을 적용하지 않습니다. main path와 identity path를 먼저 합친 뒤 ReLU를 적용합니다. 이것이 전형적인 post-activation ResNet V1 block입니다.

downsample(x)

다음 중 하나라도 성립하면 identity를 그대로 더할 수 없습니다.

  • spatial size가 다름

  • channel 수가 다름 예를 들어 main path가 [N, 16, 64, 64]에서 [N, 32, 32, 32]로 변하면 identity도 일반적으로 1×1 Conv, stride=2와 normalization을 거쳐 [N, 32, 32, 32]가 되어야 합니다.

out += identity

두 Tensor는 각 차원이 동일하거나 broadcasting 가능한 상태여야 합니다. Residual block에서는 의도하지 않은 broadcasting보다 완전히 같은 shape를 요구하는 것이 안전합니다. TorchVision의 실제 구현에서도 stride가 1이 아니거나 입력 channel과 출력 channel이 다르면 projection downsample을 구성합니다.

2.3 Runtime hook의 역할

Forward hook은 실제 Tensor 입력으로 모델을 실행하면서 등록된 module의 입력과 출력을 관찰합니다. 장점:

  • 실제 batch·image size에서 정확한 shape 확인

  • 조건문으로 선택된 실제 경로 확인

  • min, max, mean, NaN 비율 같은 값 기반 통계 확인

  • tracing을 지원하지 않는 Python·custom operator에도 사용 가능 한계:

  • F.relu, operator.add, .flatten()처럼 module이 아닌 연산은 일반 module hook으로 보이지 않음

  • 한 번 실행된 경로만 관찰함

  • 그래프를 직접 편집하는 IR이 아님

  • hook 등록과 제거 lifecycle을 직접 관리해야 함

2.4 torch.fx의 mental model

torch.fx는 nn.Module을 분석하고 변환하기 위한 toolkit입니다. 대표적인 흐름은 다음 세 단계입니다.

  1. Symbolic tracing: Python forward를 실행하되 실제 Tensor 대신 Proxy를 사용해 연산 기록

  2. Intermediate representation: 연산을 Graph와 Node 객체로 표현

  3. GraphModule 생성: 수정된 graph에서 다시 실행 가능한 Python 코드를 생성

from torch.fx import symbolic_trace

graph_module = symbolic_trace(model)

Tracer가 forward에 Proxy를 전달하면 다음 연산은 실제 계산 결과 대신 새 graph node를 만듭니다.

y = self.conv(x)
z = y + x
z = z.flatten(1)

결과적으로 call_module, call_function, call_method node가 만들어집니다. 중요한 점은 FX graph가 일반적으로 CUDA kernel이나 ATen operator 수준까지 완전히 낮아진 그래프는 아니라는 것입니다. Python 프로그램의 module·function·method 호출을 비교적 높은 수준에서 표현합니다.

2.5 FX Node의 다섯 가지 핵심 op

각 node에는 op, target, args, kwargs, users가 있습니다.

placeholder

forward의 입력입니다. plain text placeholder x

get_attr

module에 저장된 parameter, buffer 또는 constant attribute를 가져옵니다. plain text get_attr scale

call_module

등록된 submodule을 호출합니다. target은 module 경로입니다. plain text call_module stem.0 call_module layer1.conv1

call_function

Python 또는 PyTorch function을 호출합니다. plain text call_function operator.add call_function torch.nn.functional.relu

call_method

Tensor method를 호출합니다. plain text call_method flatten call_method permute 마지막 output node는 graph의 반환값을 나타냅니다.

2.6 args, kwargs, users

node.args에는 positional input이 들어갑니다. 이 값은 다른 Node, 상수 또는 중첩된 tuple/list/dict가 될 수 있습니다.

for node in graph_module.graph.nodes:
    print(node.name)
    print("  op:", node.op)
    print("  target:", node.target)
    print("  args:", node.args)
    print("  kwargs:", node.kwargs)
    print("  users:", list(node.users))

users는 해당 node의 출력을 소비하는 downstream node를 보여줍니다. Graph rewrite에서 특정 node를 제거하기 전에 누가 그 출력을 사용하는지 확인할 수 있습니다.

2.7 Symbolic tracing과 control flow

다음처럼 module 설정값에 의해 결정되는 branch는 trace 시점에 한쪽 경로가 고정될 수 있습니다.

if self.use_projection:
    x = self.projection(x)

반면 Tensor 값에 의해 결정되는 branch는 일반적인 symbolic trace가 판단할 수 없습니다.

if x.mean() > 0:
    return self.positive_path(x)
else:
    return self.negative_path(x)

x.mean() > 0의 결과도 Proxy이므로 Python이 이를 True 또는 False로 바꿀 수 없습니다. 실제 데이터에 따라 매번 다른 graph가 필요하기 때문입니다.

3. 실제 모델과 코드 구조 분석

초음파 grayscale 입력을 위한 작은 residual classifier를 사용합니다.

import torch
import torch.nn as nn
import torch.nn.functional as F


class BasicBlock(nn.Module):
    def __init__(self, in_channels, out_channels, stride=1):
        super().__init__()

        self.conv1 = nn.Conv2d(
            in_channels,
            out_channels,
            kernel_size=3,
            stride=stride,
            padding=1,
            bias=False,
        )
        self.bn1 = nn.BatchNorm2d(out_channels)

        self.conv2 = nn.Conv2d(
            out_channels,
            out_channels,
            kernel_size=3,
            stride=1,
            padding=1,
            bias=False,
        )
        self.bn2 = nn.BatchNorm2d(out_channels)

        if stride != 1 or in_channels != out_channels:
            self.projection = nn.Sequential(
                nn.Conv2d(
                    in_channels,
                    out_channels,
                    kernel_size=1,
                    stride=stride,
                    bias=False,
                ),
                nn.BatchNorm2d(out_channels),
            )
        else:
            self.projection = nn.Identity()

    def forward(self, x):
        identity = self.projection(x)

        out = self.conv1(x)
        out = self.bn1(out)
        out = F.relu(out)

        out = self.conv2(out)
        out = self.bn2(out)

        out = out + identity
        return F.relu(out)


class UltrasoundResidualNet(nn.Module):
    def __init__(self, num_classes=2):
        super().__init__()

        self.stem = nn.Sequential(
            nn.Conv2d(
                1,
                16,
                kernel_size=3,
                stride=2,
                padding=1,
                bias=False,
            ),
            nn.BatchNorm2d(16),
            nn.ReLU(inplace=False),
        )

        self.layer1 = BasicBlock(16, 16, stride=1)
        self.layer2 = BasicBlock(16, 32, stride=2)
        self.pool = nn.AdaptiveAvgPool2d(1)
        self.head = nn.Linear(32, num_classes)

    def forward(self, x):
        x = self.stem(x)
        x = self.layer1(x)
        x = self.layer2(x)
        x = self.pool(x)
        x = x.flatten(1)
        return self.head(x)

입력이 [2, 1, 128, 128]일 때 예상 shape은 다음과 같습니다. plain text input [2, 1, 128, 128] stem [2, 16, 64, 64] layer1 main [2, 16, 64, 64] layer1 identity [2, 16, 64, 64] layer1 output [2, 16, 64, 64] layer2 main [2, 32, 32, 32] layer2 projection [2, 32, 32, 32] layer2 output [2, 32, 32, 32] pool [2, 32, 1, 1] flatten [2, 32] head [2, 2] layer1.projection은 Identity이므로 값과 shape를 그대로 전달합니다. layer2.projection은 channel을 16에서 32로 바꾸고 spatial size를 절반으로 줄입니다.

4. 수정 가능한 지점과 설계 trade-off

4.1 Hook과 FX 중 무엇을 선택할까?

목적 Runtime hook torch.fx
실제 Tensor shape와 값 확인 매우 적합 ShapeProp 또는 실행 필요
data-dependent branch 관찰 실행된 경로만 가능 기본 symbolic trace는 제한적
functional operation 확인 제한적 가능
graph 자동 수정 부적합 적합
custom CUDA op 포함 모델 실행 가능하면 관찰 가능 tracer 설정이 필요할 수 있음
운영 중 간단한 진단 가능 graph 생성 비용과 호환성 검토 필요

실무에서는 둘 중 하나만 고르기보다 다음 순서가 유용합니다.

  1. Module tree로 구조 확인

  2. Hook으로 실제 shape·값 검증

  3. FX로 연산 연결과 변환 지점 확인

4.2 Functional activation과 module activation

x = F.relu(x)

FX에서는 일반적으로 call_function node로 나타납니다.

self.relu = nn.ReLU()
x = self.relu(x)

FX에서는 call_module로 나타납니다. Module 방식은 activation을 이름으로 찾거나 교체하기 쉽고 module hook도 사용할 수 있습니다. Functional 방식은 코드가 간결하지만 module tree와 일반 hook에서 보이지 않습니다. FX를 사용하면 functional operation도 찾을 수 있습니다.

4.3 In-place operation

TorchVision BasicBlock은 out += identity와 ReLU(inplace=True)를 사용합니다. 메모리를 일부 절약할 수 있지만 다음 상황에서는 분석과 변경을 복잡하게 할 수 있습니다.

  • 중간 activation을 다른 branch에서도 사용

  • custom backward 구현

  • graph rewrite 후 alias 관계 변경

  • activation을 시각화하거나 여러 loss에서 재사용 분석·연구 단계에서는 우선 out = out + identity, inplace=False로 명확성을 확보한 뒤 성능을 측정해 in-place 최적화를 검토하는 것이 안전합니다.

4.4 ReLU를 SiLU로 교체

SiLU는 음수 영역에서도 완전히 0이 아닌 gradient를 제공하고 부드러운 함수입니다. 초음파의 약한 echo feature를 처리할 때 성능 차이를 실험할 가치가 있습니다. Trade-off:

  • ReLU: 단순하고 빠르며 양자화·배포 친화적

  • SiLU: 부드러운 gradient, 일부 모델에서 정확도 개선 가능

  • SiLU는 backend와 정밀도에 따라 latency가 증가할 수 있음

  • pretrained ReLU 모델의 activation을 바꾸면 feature 분포가 달라지므로 추가 학습 필요

4.5 FX GraphModule과 checkpoint

단순히 functional activation만 교체하면 parameter shape는 변하지 않습니다. 그러나 submodule을 추가·삭제하거나 이름을 바꾸는 transformation은 state_dict key 호환성을 바꿀 수 있습니다. 변환 전후에 다음을 비교해야 합니다.

before = set(model.state_dict())
after = set(graph_module.state_dict())

print("missing:", before - after)
print("added:", after - before)

5. 직접 실행 실습

실습 A: Runtime hook으로 실제 실행 순서 확인

import torch
import torch.nn as nn


model = UltrasoundResidualNet().eval()
records = []
handles = []


def make_hook(name):
    def hook(module, inputs, output):
        records.append({
            "name": name,
            "type": type(module).__name__,
            "input": tuple(inputs[0].shape),
            "output": tuple(output.shape),
        })
    return hook


try:
    for name, module in model.named_modules():
        if name and len(list(module.children())) == 0:
            handles.append(
                module.register_forward_hook(make_hook(name))
            )

    with torch.no_grad():
        logits = model(torch.randn(2, 1, 128, 128))

finally:
    for handle in handles:
        handle.remove()


for row in records:
    print(
        f"{row['name']:24s} "
        f"{row['type']:18s} "
        f"{row['input']} -> {row['output']}"
    )

print("logits:", tuple(logits.shape))

확인할 내용:

  • layer1.projection의 Identity도 실행 기록에 나타납니다.

  • layer2.projection.0의 입력은 [2, 16, 64, 64], 출력은 [2, 32, 32, 32]입니다.

  • out + identity, F.relu, flatten은 module hook에 나타나지 않습니다.

실습 B: FX graph와 생성된 Python 코드 읽기

from torch.fx import symbolic_trace


model = UltrasoundResidualNet().eval()
traced = symbolic_trace(model)

print("[Graph]")
print(traced.graph)

print("\n[Generated Python]")
print(traced.code)

print("\n[Node details]")
for node in traced.graph.nodes:
    print(
        f"{node.name:24s} "
        f"op={node.op:14s} "
        f"target={node.target}"
    )

관찰 포인트:

  • stem.0, convolution, BatchNorm, projection은 call_module

  • F.relu는 call_function

  • residual 덧셈도 call_function

  • flatten은 call_method

  • 사용자 정의 BasicBlock 내부 연산은 graph에 펼쳐짐

  • Conv2d, BatchNorm2d 같은 표준 module 내부 계산은 기본적으로 하나의 leaf call_module로 유지됨

실습 C: ShapeProp으로 node별 shape 추가

Symbolic trace 자체는 실제 Tensor shape를 반드시 계산하지 않습니다. 예제 입력으로 graph를 실행하며 metadata를 채우겠습니다.

import torch
from torch.fx.passes.shape_prop import ShapeProp


sample = torch.randn(2, 1, 128, 128)
ShapeProp(traced).propagate(sample)


for node in traced.graph.nodes:
    tensor_meta = node.meta.get("tensor_meta")

    if tensor_meta is None:
        shape = "-"
        dtype = "-"
    else:
        shape = tuple(tensor_meta.shape)
        dtype = tensor_meta.dtype

    print(
        f"{node.name:24s} "
        f"{str(shape):24s} "
        f"{dtype}"
    )

ShapeProp은 graph를 실제로 실행합니다. 따라서 다음을 주의해야 합니다.

  • 모델과 sample이 같은 device에 있어야 함

  • parameter와 입력 dtype이 호환돼야 함

  • BatchNorm running statistics를 바꾸지 않도록 분석 시 eval() 권장

  • 매우 큰 입력은 실제 메모리를 사용하므로 작은 대표 입력 사용

실습 D: FX graph에서 F.relu를 F.silu로 교체

import torch
import torch.nn.functional as F
from torch.fx import symbolic_trace


model = UltrasoundResidualNet().eval()
traced = symbolic_trace(model)

sample = torch.randn(2, 1, 128, 128)

with torch.no_grad():
    original_output = traced(sample)


replaced = 0

for node in list(traced.graph.nodes):
    if node.op == "call_function" and node.target is F.relu:
        with traced.graph.inserting_after(node):
            new_node = traced.graph.call_function(
                F.silu,
                args=node.args,
                kwargs={},
            )

        node.replace_all_uses_with(new_node)
        traced.graph.erase_node(node)
        replaced += 1


traced.graph.lint()
traced.recompile()

with torch.no_grad():
    modified_output = traced(sample)


print("replaced nodes:", replaced)
print("original shape:", tuple(original_output.shape))
print("modified shape:", tuple(modified_output.shape))
print(
    "max abs difference:",
    (original_output - modified_output).abs().max().item()
)

print("\n[Modified Python]")
print(traced.code)

예상 결과:

  • 두 BasicBlock의 ReLU가 각각 두 번씩 있으므로 functional ReLU 4개가 교체됩니다.

  • stem의 nn.ReLU는 call_module이므로 이 코드에서는 교체되지 않습니다.

  • 출력 shape는 모두 [2, 2]입니다.

  • activation이 달라졌으므로 출력 값의 차이는 0이 아닙니다. Graph 수정 후에는 다음 두 호출이 중요합니다.

traced.graph.lint()
traced.recompile()

lint()는 node 순서, ownership, 존재하지 않는 target 같은 graph 불일치를 검사합니다. recompile()은 변경된 graph로 실행할 Python forward 코드를 다시 생성합니다.

실습 E: Data-dependent control flow 실패 재현

import torch
import torch.nn as nn
from torch.fx import symbolic_trace


class DynamicBranch(nn.Module):
    def __init__(self):
        super().__init__()
        self.positive = nn.Conv2d(1, 1, 3, padding=1)
        self.negative = nn.Conv2d(1, 1, 1)

    def forward(self, x):
        if x.mean() > 0:
            return self.positive(x)
        return self.negative(x)


try:
    symbolic_trace(DynamicBranch())
except Exception as error:
    print(type(error).__name__)
    print(error)

Tracer는 x.mean() > 0을 실제 Boolean으로 결정할 수 없으므로 control-flow 관련 오류가 발생합니다. 대응 방법:

  • branch를 Tensor 연산인 torch.where 또는 mask 조합으로 표현

  • branch 조건을 input data가 아닌 고정된 module configuration으로 변경

  • custom Tracer에서 특정 영역을 leaf module로 처리

  • symbolic trace보다 동적 제어 흐름 지원 범위가 넓은 torch.export 검토

  • 목적이 관찰이라면 runtime hook이나 profiler 사용

7. 복습 문제

  1. print(model)에는 residual 덧셈이나 F.relu가 나타나지 않는 이유는 무엇인가요?

  2. Runtime hook과 FX graph의 가장 중요한 차이를 한 가지씩 설명하세요.

  3. FX node에서 call_module, call_function, call_method는 각각 무엇을 의미하나요?

  4. x.mean() > 0에 따라 Python if branch를 선택하는 모델이 symbolic_trace()에서 실패하는 이유는 무엇인가요?

  5. FX graph에서 node를 교체한 뒤 호출해야 하는 두 메서드와 각각의 목적은 무엇인가요?

정답과 해설

  1. print(model)은 등록된 submodule tree를 보여줍니다. residual 덧셈은 Tensor 연산이고 F.relu는 functional API이므로 submodule로 등록되지 않습니다. 실행 연결을 보려면 FX graph나 다른 graph capture 방식이 필요합니다.

  2. Runtime hook은 실제 Tensor로 실행된 module의 shape와 값을 관찰하지만 편집 가능한 전체 연산 graph를 만들지는 않습니다. FX는 Proxy로 연산 연결을 기록해 편집 가능한 GraphModule을 만들지만 data-dependent Python control flow에는 제한이 있습니다.

  3. call_module은 등록된 submodule 호출, call_function은 Python/PyTorch 함수 호출, call_method는 Tensor와 같은 객체의 method 호출을 의미합니다. target을 함께 읽어 실제 대상이 convolution인지, operator.add인지, flatten인지 확인해야 합니다.

  4. 조건식의 결과도 실제 Boolean이 아니라 Proxy입니다. Python if는 즉시 True 또는 False를 요구하지만 tracer는 실제 입력 값이 없으므로 어느 branch를 기록할지 결정할 수 없습니다.

  5. graph.lint()는 graph의 구조적 일관성을 검사합니다. GraphModule.recompile()은 변경된 graph로 실행할 Python 코드를 다시 생성합니다. 둘을 생략하면 잘못된 graph가 남거나 수정이 실제 forward에 반영되지 않을 수 있습니다.
