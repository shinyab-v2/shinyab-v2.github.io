논문을 구현 가능한 Specification으로 바꾸기

논문의 architecture 그림을 그대로 코딩하지 않습니다. tensor contract, equation, hidden assumption, training recipe를 분리해 구현하고 unit test와 ablation으로 검증합니다.

1. 논문을 세 층으로 읽는다

Architecture: module과 연결 관계. Tensor contract: 각 지점의 shape과 dtype. Training recipe: loss, optimizer, LR, augmentation, initialization입니다. 세 층을 섞지 않아야 구현 차이를 찾기 쉽습니다.

2. 먼저 shape table을 만든다

StageInputOperationOutput
stem[B,1,512,512]Conv s=2[B,64,256,256]
block1[B,64,256,256]Residual[B,64,256,256]
neckC3,C4,C5FPN/PANP3,P4,P5

숫자는 구현하려는 논문의 실제 설정으로 교체해야 합니다. 목적은 코드를 쓰기 전에 모든 add/concat/reshape가 가능한지 검증하는 것입니다.

3. Equation을 코드로 번역한다

수식의 각 기호가 어떤 tensor dimension인지 적습니다. 예를 들어 attention의 QKᵀ/√d라면 Q/K shape를 먼저 적고 matrix multiplication 결과를 계산한 뒤 구현합니다.

4. Hidden assumptions를 찾는다

논문 본문에 padding, interpolation mode, normalization epsilon 같은 세부사항이 없을 수 있습니다. 이때 임의 선택을 논문의 사실처럼 취급하지 말고 implementation decision으로 기록합니다. 공식 공개 코드가 있다면 우선 확인합니다.

5. Module 단위로 구현한다

class ProposedBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        ...
    def forward(self, x):
        ...
        assert y.shape == x.shape
        return y

처음부터 전체 network를 만들기보다 논문의 novelty가 있는 block 하나를 독립 구현합니다.

6. Unit Test

x = torch.randn(2, 64, 32, 32, requires_grad=True)
y = block(x)
assert y.shape == x.shape
y.mean().backward()
assert x.grad is not None
assert torch.isfinite(x.grad).all()

shape, finite output, backward 가능 여부, deterministic reference가 있으면 numerical equivalence까지 확인합니다.

7. Parameter/FLOPs sanity check

논문이 parameter 수나 FLOPs를 제공한다면 구현 결과와 비교합니다. 큰 차이가 있으면 channel, repeated block count, bias, projection 등을 잘못 해석했을 가능성이 있습니다.

8. Ablation으로 논문의 claim을 확인한다

“이 module이 small-object 성능을 높인다”는 주장이 있다면 baseline과 proposed module 외의 조건을 최대한 동일하게 유지합니다. 전체 metric뿐 아니라 small-lesion subgroup을 분리해 확인해야 주장과 실험이 연결됩니다.

연구개발 기록 규칙: Paper says / Official code does / We decided 세 칸으로 나눠 기록하면 재현성과 코드 리뷰 품질이 크게 좋아집니다.

9. Ultrasound 적용 workflow

새 논문의 detection neck을 breast ultrasound에 적용한다면 먼저 공개 dataset/기존 internal baseline에서 구조 자체를 검증하고, 이후 ultrasound 특화 augmentation과 loss 변경을 분리해서 실험합니다. 동시에 여러 요소를 바꾸면 개선 원인을 알 수 없습니다.

10. 실습

  1. 관심 논문 하나를 선택하고 novelty block 하나만 고릅니다.
  2. 입출력 tensor contract를 작성합니다.
  3. 논문에 없는 구현 결정 5개를 찾습니다.
  4. PyTorch module과 shape/backward unit test를 만듭니다.
  5. baseline 대비 parameter/FLOPs/latency/metric 비교표를 설계합니다.

11. 복습 문제

  1. 논문 그림만 보고 바로 구현하면 위험한 이유는? 세부 tensor/operation 조건이 생략될 수 있다.
  2. 왜 shape table을 먼저 만드는가? 연산 contract를 코드 전에 검증하기 위해서다.
  3. 공식 코드와 논문이 다르면? 차이를 기록하고 어떤 것을 재현할지 명시한다.
  4. unit test에 backward를 넣는 이유는? training graph까지 유효한지 보기 위해서다.
  5. ablation의 핵심은? 한 번에 가능한 한 하나의 요인만 비교하는 것.
