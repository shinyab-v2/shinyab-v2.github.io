AI 전문 개발 학습 #01 — Tensor Shape로 모델 구조 읽기

NCHW와 tensor/Conv stride를 구분하고 Conv2d 출력 크기·파라미터 수를 계산한다. residual/add/concat의 shape 계약을 이해하며 forward hook으로 중간 shape를 추적하고, 입력 채널·해상도·분류 head를 안전하게 수정한다.

학습 개요

예상 시간: 38분
오늘의 핵심은 모델을 레이어 이름이 아니라 tensor shape의 변환 그래프로 읽는 것입니다. 공개 모델을 가져와 학습·배포한 경험이 있다면, 이제부터는 각 연산이 (N, C, H, W)를 어떻게 바꾸고 어느 지점에서 계약(contract)이 깨지는지를 추적합니다.

1. 시간표와 학습 목표

시간 학습 내용 완료 기준
0–4분 NCHW, rank, tensor stride shape, ndim, stride()를 구분한다
4–11분 Conv2d 출력 크기와 파라미터 수 손으로 계산하고 코드 결과를 예측한다
11–16분 residual/add/concat 제약 merge 전 shape 계약을 설명한다
16–25분 forward hook 실습 모델 중간 shape를 자동 출력한다
25–31분 입력·해상도·head 수정 수정 범위와 trade-off를 판단한다
31–35분 의도적 shape 오류 디버깅 오류 지점을 찾고 projection으로 고친다
35–38분 체크리스트와 복습 문제 5문제 중 4문제 이상 설명한다

학습 후에는 다음을 할 수 있어야 합니다.

  • 4D 이미지 tensor를 NCHW로 읽고 rank와 memory stride를 구분한다.

  • Conv2d의 출력 공간 크기와 학습 파라미터 수를 계산한다.

  • residual addition과 channel concatenation이 요구하는 shape 조건을 판단한다.

  • forward hook으로 기존 PyTorch 모델의 중간 tensor shape를 추적한다.

  • 입력 채널, 입력 해상도, 출력 head를 바꿀 때 무엇이 깨질 수 있는지 사전에 점검한다.

  • shape 오류 메시지를 결과가 아니라 최초로 계약이 깨진 지점까지 역추적한다.

2. Tensor shape를 모델의 인터페이스로 읽기

2.1 NCHW와 rank

이미지용 PyTorch Conv2d의 대표 입력 형식은 (N, C, H, W)입니다.
축 의미 예: (8, 3, 224, 224)
N batch size 이미지 8장
C channel/feature map 수 RGB 3채널
H height 224 pixels
W width 224 pixels

Rank는 축의 개수입니다. (8, 3, 224, 224)는 rank 4이고, x.ndim == 4입니다. Rank와 각 축의 크기는 다릅니다. 예를 들어 (1, 1, 512, 512)와 (32, 128, 7, 7)은 모두 rank 4입니다.

import torch

x = torch.randn(8, 3, 224, 224)
print(x.shape)    # torch.Size([8, 3, 224, 224])
print(x.ndim)     # 4
print(x.numel())  # 8 * 3 * 224 * 224

실무에서는 각 tensor에 의미가 드러나는 주석을 붙이십시오.


# x: [N, C, H, W]

# logits: [N, num_classes]

# mask_logits: [N, num_classes, H, W]

[8, 1]과 [8]은 원소 수는 같아도 다른 계약입니다. squeeze()를 축 지정 없이 사용하면 batch size가 1일 때 batch 축까지 사라질 수 있으므로 squeeze(dim=...) 또는 flatten(start_dim=1)처럼 의도를 명시합니다.

2.2 두 종류의 stride를 구분하기

딥러닝 코드에서 stride는 두 의미로 쓰입니다.

  1. Tensor memory stride: 특정 축을 1만큼 이동할 때 저장소에서 몇 원소를 건너뛰는지 나타냅니다.

  2. Convolution stride: kernel이 입력 공간을 몇 칸씩 이동하는지 나타냅니다.

x = torch.randn(2, 3, 32, 32)
print(x.shape)          # [2, 3, 32, 32]
print(x.stride())       # 보통 (3072, 1024, 32, 1)
print(x.is_contiguous())

y = x.permute(0, 2, 3, 1)  # NCHW -> NHWC view
print(y.shape)               # [2, 32, 32, 3]
print(y.stride())            # 메모리 배치는 그대로이므로 stride가 달라짐
print(y.is_contiguous())     # False

y = y.contiguous()           # 필요할 때만 실제 연속 메모리로 복사

permute는 축의 해석을 바꾸지만 대개 데이터를 즉시 복사하지 않습니다. 이 때문에 non-contiguous tensor에 view()가 실패할 수 있습니다. reshape()는 가능한 경우 view를 만들고 필요하면 복사할 수 있으므로 더 관대하지만, 복사 비용이 숨어 있을 수 있습니다. 성능 문제를 볼 때는 shape뿐 아니라 stride()와 is_contiguous()도 확인합니다.

3. Conv2d 출력 크기와 파라미터 수

입력이 (N, C_in, H_in, W_in)이고 kernel, stride, padding, dilation이 축별로 각각 K, S, P, D일 때 출력 높이는 다음과 같습니다. $ H_{out}=\left\lfloor\frac{H_{in}+2P_h-D_h(K_h-1)-1}{S_h}+1\right\rfloor $ 폭 W_out도 같은 식을 사용합니다. 출력 tensor는 (N, C_out, H_out, W_out)입니다. 공식 Conv2d 문서도 같은 규칙을 정의합니다: PyTorch Conv2d

3.1 계산 예제

conv = torch.nn.Conv2d(
    in_channels=3,
    out_channels=64,
    kernel_size=7,
    stride=2,
    padding=3,
    bias=True,
)
x = torch.randn(8, 3, 224, 224)
y = conv(x)
print(y.shape)  # [8, 64, 112, 112]

높이 계산: floor((224 + 2×3 - 1×(7-1) - 1) / 2 + 1) = floor(112.5) = 112 파라미터 수는 groups까지 포함하면 다음과 같습니다. $ \text{weight params}=C_{out}\times\frac{C_{in}}{groups}\times K_h\times K_w $ Bias가 있으면 C_out을 더합니다. 위 레이어는 64×3×7×7 + 64 = 9,472개입니다. Batch size와 입력 해상도는 파라미터 수를 바꾸지 않지만, activation memory와 연산량은 바꿉니다.

3.2 바로 풀어보기

입력이 (8, 32, 55, 73)이고 Conv2d(32, 64, kernel_size=3, stride=2, padding=1, bias=False)라면:

  • H_out = 28

  • W_out = 37

  • 출력 shape = (8, 64, 28, 37)

  • 파라미터 수 = 64×32×3×3 = 18,432 가장 흔한 실수는 padding=1이면 무조건 공간 크기가 유지된다고 생각하는 것입니다. 이는 보통 kernel=3, dilation=1, stride=1일 때만 맞습니다. stride=2이면 대략 절반이 되고, 홀수 입력은 floor 규칙 때문에 한 칸 차이가 날 수 있습니다. —

4. residual/add/concat의 shape 계약

4.1 Add: 원칙적으로 모든 축이 같아야 한다

Residual block의 out + identity는 (N, C, H, W)가 정확히 같아야 합니다.

assert out.shape == identity.shape
out = out + identity

PyTorch의 일반 덧셈은 broadcasting을 지원하므로 (N,C,H,W) + (N,C,1,1)도 실행됩니다. 하지만 residual 연결에서 우연한 broadcasting은 설계 오류를 숨길 수 있습니다. 따라서 merge 직전에 exact-shape assertion을 두는 것이 안전합니다. 채널 또는 해상도가 달라지면 skip branch에 projection을 둡니다.

projection = torch.nn.Conv2d(
    in_channels=16,
    out_channels=32,
    kernel_size=1,
    stride=2,
    bias=False,
)

1×1, stride=2 projection은 C:16→32, H/W:56→28을 동시에 맞춥니다. 대신 파라미터와 연산이 늘며 identity가 더 이상 완전한 무변환 경로는 아닙니다.

4.2 Concat: 합칠 축 이외의 모든 축이 같아야 한다

a = torch.randn(4, 32, 28, 28)
b = torch.randn(4, 16, 28, 28)
c = torch.cat([a, b], dim=1)
print(c.shape)  # [4, 48, 28, 28]
Channel concat에서는 N, H, W가 같아야 하고 출력 channel은 합이 됩니다. 따라서 다음 레이어의 in_channels도 48이어야 합니다. 공식 문서: PyTorch torch.cat
연산 입력 조건 출력 주요 trade-off
add 보통 전체 shape 동일 shape 유지 채널 수 증가 없이 정보 결합
cat(dim=1) N/H/W 동일 채널 합 정보 보존이 좋지만 메모리와 다음 Conv 비용 증가
stack 전체 shape 동일 새 축 추가 concat과 의미가 다름

U-Net 계열에서는 encoder와 decoder feature의 H/W가 한 칸 다를 수 있습니다. 입력 크기가 downsampling 배수와 맞지 않거나 padding 규칙이 다르기 때문입니다. interpolate나 crop으로 억지로 맞추기 전에 어느 branch의 좌표계와 해상도를 기준으로 삼을지 먼저 결정해야 합니다.

5. 실습 A — forward hook으로 중간 tensor shape 추적

아래 코드는 그대로 실행할 수 있는 독립 예제입니다. Leaf module마다 hook을 달고 입력·출력 shape를 출력합니다. Hook은 forward()가 끝난 뒤 호출되며, 반환된 handle의 remove()로 해제해야 합니다. 공식 문서: PyTorch Module.register_forward_hook

import torch
import torch.nn as nn


def shape_tree(obj):
    """Tensor, tuple/list, dict가 섞인 입출력을 읽기 좋은 shape로 변환."""
    if isinstance(obj, torch.Tensor):
        return tuple(obj.shape)
    if isinstance(obj, (tuple, list)):
        return [shape_tree(item) for item in obj]
    if isinstance(obj, dict):
        return {key: shape_tree(value) for key, value in obj.items()}
    return type(obj).__name__


class Add(nn.Module):
    """함수형 add도 hook에서 보이게 만든 작은 module."""
    def forward(self, left, right):
        if left.shape != right.shape:
            raise RuntimeError(
                f"Residual shape mismatch: {tuple(left.shape)} vs {tuple(right.shape)}"
            )
        return left + right


class ResidualBlock(nn.Module):
    def __init__(self, in_ch, out_ch, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(
            in_ch, out_ch, kernel_size=3, stride=stride, padding=1, bias=False
        )
        self.bn1 = nn.BatchNorm2d(out_ch)
        self.relu1 = nn.ReLU(inplace=False)
        self.conv2 = nn.Conv2d(
            out_ch, out_ch, kernel_size=3, stride=1, padding=1, bias=False
        )
        self.bn2 = nn.BatchNorm2d(out_ch)

        if stride != 1 or in_ch != out_ch:
            self.skip = nn.Sequential(
                nn.Conv2d(
                    in_ch, out_ch, kernel_size=1, stride=stride, bias=False
                ),
                nn.BatchNorm2d(out_ch),
            )
        else:
            self.skip = nn.Identity()

        self.add = Add()
        self.relu2 = nn.ReLU(inplace=False)

    def forward(self, x):
        identity = self.skip(x)
        out = self.relu1(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out = self.add(out, identity)
        return self.relu2(out)


class ShapeNet(nn.Module):
    def __init__(self, in_channels=3, num_classes=5):
        super().__init__()
        self.stem = nn.Sequential(
            nn.Conv2d(
                in_channels, 16, kernel_size=3, stride=2, padding=1, bias=False
            ),
            nn.BatchNorm2d(16),
            nn.ReLU(inplace=False),
        )
        self.block1 = ResidualBlock(16, 16, stride=1)
        self.block2 = ResidualBlock(16, 32, stride=2)
        self.pool = nn.AdaptiveAvgPool2d((1, 1))
        self.flatten = nn.Flatten(start_dim=1)
        self.head = nn.Linear(32, num_classes)

    def forward(self, x):
        x = self.stem(x)
        x = self.block1(x)
        x = self.block2(x)
        x = self.pool(x)
        x = self.flatten(x)
        return self.head(x)


def install_shape_hooks(model):
    handles = []

    def make_hook(name):
        def hook(module, args, output):
            print(
                f"{name:24s} {module.__class__.__name__:18s} "
                f"in={shape_tree(args)} -> out={shape_tree(output)}"
            )
        return hook

    for name, module in model.named_modules():
        # 중복 출력을 줄이기 위해 자식이 없는 leaf module만 추적한다.
        if name and len(list(module.children())) == 0:
            handles.append(module.register_forward_hook(make_hook(name)))
    return handles


if __name__ == "__main__":
    torch.manual_seed(0)
    model = ShapeNet(in_channels=3, num_classes=5).eval()
    x = torch.randn(2, 3, 224, 224)
    handles = install_shape_hooks(model)

    try:
        with torch.inference_mode():
            logits = model(x)
        print("final:", tuple(logits.shape))
    finally:
        for handle in handles:
            handle.remove()

예상 결과의 핵심 줄

plain text stem.0 Conv2d in=[(2, 3, 224, 224)] -> out=(2, 16, 112, 112) block1.add Add in=[(2, 16, 112, 112), (2, 16, 112, 112)] -> out=(2, 16, 112, 112) block2.conv1 Conv2d in=[(2, 16, 112, 112)] -> out=(2, 32, 56, 56) block2.skip.0 Conv2d in=[(2, 16, 112, 112)] -> out=(2, 32, 56, 56) block2.add Add in=[(2, 32, 56, 56), (2, 32, 56, 56)] -> out=(2, 32, 56, 56) pool AdaptiveAvgPool2d in=[(2, 32, 56, 56)] -> out=(2, 32, 1, 1) flatten Flatten in=[(2, 32, 1, 1)] -> out=(2, 32) head Linear in=[(2, 32)] -> out=(2, 5) final: (2, 5) 실제 출력에는 BatchNorm과 ReLU 줄도 포함됩니다. Hook 사용 시 주의점:

  • torch.add, torch.cat, F.interpolate, torch.flatten 같은 함수형 연산은 module hook만으로 보이지 않습니다. 중요한 연산은 Add, nn.Flatten처럼 module로 감싸거나 forward()에 assertion/log를 둡니다.

  • 한 module이 여러 번 재사용되면 같은 이름의 hook이 여러 번 호출됩니다.

  • hook에서 output을 반환하면 output을 바꿀 수 있습니다. 관찰 목적이라면 아무것도 반환하지 않습니다.

  • 학습 루프에 hook을 계속 남겨두면 로그·메모리·속도 문제가 생길 수 있으므로 finally에서 제거합니다.

  • 복잡한 모델은 모든 레이어를 찍지 말고 Conv/Linear/Pooling/merge 지점으로 필터링합니다.

6. 입력 채널·해상도·출력 head를 안전하게 수정하기

6.1 입력 채널 변경

RGB pretrained backbone을 1채널 초음파 입력에 적용할 때 확인할 항목은 세 가지입니다.

  1. 첫 Conv의 in_channels

  2. 입력 normalization의 mean/std와 intensity scaling

  3. pretrained weight를 새 채널에 어떻게 매핑할지 RGB 3채널을 grayscale 1채널로 직접 바꾸는 예:

def rgb_conv_to_grayscale(old_conv: nn.Conv2d) -> nn.Conv2d:
    if old_conv.in_channels != 3 or old_conv.groups != 1:
        raise ValueError("이 예제는 일반적인 groups=1 RGB Conv2d만 지원합니다.")

    new_conv = nn.Conv2d(
        in_channels=1,
        out_channels=old_conv.out_channels,
        kernel_size=old_conv.kernel_size,
        stride=old_conv.stride,
        padding=old_conv.padding,
        dilation=old_conv.dilation,
        groups=1,
        bias=old_conv.bias is not None,
        padding_mode=old_conv.padding_mode,
    ).to(device=old_conv.weight.device, dtype=old_conv.weight.dtype)

    with torch.no_grad():
        # RGB filter의 평균을 초기값으로 사용해 activation scale을 과도하게 키우지 않는다.
        new_conv.weight.copy_(old_conv.weight.mean(dim=1, keepdim=True))
        if old_conv.bias is not None:
            new_conv.bias.copy_(old_conv.bias)
    return new_conv


model = ShapeNet(in_channels=3, num_classes=5)
model.stem[0] = rgb_conv_to_grayscale(model.stem[0])
test_x = torch.randn(2, 1, 224, 224)
assert model(test_x).shape == (2, 5)

평균 대신 RGB weight의 합을 쓰면 동일 grayscale 영상을 RGB 세 채널에 복제했을 때 첫 Conv의 출력을 더 가깝게 보존할 수 있지만 activation 크기가 커질 수 있습니다. 어느 쪽이 최선인지는 입력 분포와 normalization에 따라 달라집니다. 짧은 calibration set으로 첫 레이어 activation의 평균·표준편차를 비교하십시오. 새 modality가 4채널 이상이고 기존 RGB와 의미가 다르면 backbone 첫 Conv를 억지로 확장하는 대신 학습 가능한 1×1 channel adapter를 앞에 둘 수 있습니다.

adapter = nn.Conv2d(new_input_channels, 3, kernel_size=1, bias=False)
model = nn.Sequential(adapter, pretrained_rgb_backbone)

이 방식은 backbone checkpoint를 그대로 유지하고 adapter만 먼저 학습할 수 있다는 장점이 있습니다. 반면 입력 채널을 3차원으로 압축하면서 정보 손실이 생길 수 있고 한 레이어의 비용이 추가됩니다. Depthwise/grouped Conv는 in_channels, out_channels, groups의 나눗셈 조건이 함께 묶이므로 일반 Conv처럼 첫 채널만 바꾸면 안 됩니다.

6.2 입력 해상도 변경

입력 해상도를 바꿀 때 Conv 파라미터 수는 그대로지만 다음은 변합니다.

  • activation memory와 FLOPs: 대체로 H×W에 비례

  • 물체가 feature map에서 차지하는 상대 크기와 effective receptive field

  • 여러 번 stride-2 downsampling 후의 홀수/짝수 정렬

  • absolute positional embedding을 쓰는 ViT 계열의 token grid

  • 고정 크기 flatten 뒤 Linear를 쓰는 head의 in_features CNN classifier는 AdaptiveAvgPool2d를 head 앞에 두면 해상도 의존성을 크게 줄일 수 있습니다. 하지만 detection/segmentation처럼 위치 정보가 필요한 모델에서 (1,1) global pooling을 넣으면 안 됩니다. 또한 입력 크기가 자유로워져도 batch 내부 tensor 크기는 일반적인 batching에서 같아야 합니다. 서로 다른 크기는 pad, resize, bucketing 또는 list 입력을 지원하는 별도 pipeline이 필요합니다.

6.3 출력 head 변경

model = ShapeNet(in_channels=3, num_classes=5)
old_in_features = model.head.in_features
model.head = nn.Linear(old_in_features, 3)

안전 점검:

  • class index와 label mapping을 새로 정의합니다.

  • loss가 출력 의미와 맞는지 확인합니다. 단일 다중분류는 보통 [N,C] logits + CrossEntropyLoss, multi-label은 [N,C] logits + BCEWithLogitsLoss입니다.

  • optimizer를 만든 뒤에 head를 교체했다면 새 파라미터가 optimizer에 들어 있지 않습니다. head 교체 후 optimizer를 다시 생성하거나 param group을 추가합니다.

  • shape가 다른 기존 head weight는 strict=False만으로 항상 무시되지 않습니다. checkpoint에서 해당 key를 제거한 뒤 backbone을 로드합니다.

state = torch.load("checkpoint.pt", map_location="cpu", weights_only=True)
state.pop("head.weight", None)
state.pop("head.bias", None)
missing, unexpected = model.load_state_dict(state, strict=False)
print("missing:", missing)
print("unexpected:", unexpected)

모델 구현에 따라 key가 fc.*, classifier.*, heads.head.*일 수 있으므로 state_dict().keys()로 실제 이름을 확인합니다.

7. 실습 B — AdaptiveAvgPool로 해상도 의존성 줄이기

AdaptiveAvgPool2d((1,1))은 입력 H/W가 무엇이든 출력 공간 크기를 1×1로 맞추고 채널 수는 유지합니다. 공식 문서: PyTorch AdaptiveAvgPool2d

import torch
import torch.nn as nn


class FlexibleClassifier(nn.Module):
    def __init__(self, in_channels=1, num_classes=7):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(in_channels, 16, 3, stride=2, padding=1),
            nn.ReLU(),
            nn.Conv2d(16, 32, 3, stride=2, padding=1),
            nn.ReLU(),
        )
        self.pool = nn.AdaptiveAvgPool2d((1, 1))
        self.flatten = nn.Flatten(1)
        self.head = nn.Linear(32, num_classes)

    def forward(self, x):
        x = self.features(x)
        x = self.pool(x)
        x = self.flatten(x)
        return self.head(x)


model = FlexibleClassifier().eval()
for height, width in [(128, 160), (224, 224), (320, 512)]:
    x = torch.randn(4, 1, height, width)
    with torch.inference_mode():
        y = model(x)
    print((height, width), "->", tuple(y.shape))
    assert y.shape == (4, 7)

예상 결과: plain text (128, 160) -> (4, 7) (224, 224) -> (4, 7) (320, 512) -> (4, 7) 추가 실습:

  1. pool = nn.AdaptiveAvgPool2d((4,4))로 바꿉니다.

  2. head = nn.Linear(32*4*4, num_classes)로 바꿉니다.

  3. 세 해상도를 다시 테스트합니다. (4,4) pooling은 거친 공간 정보를 더 보존하지만 head 파라미터가 32×16배의 입력을 받습니다. (1,1)은 가장 가볍지만 작은 병변 위치 같은 공간 정보를 global average에서 희석할 수 있습니다. —

10. 복습 문제 5개

문제 1

입력 (4, 3, 64, 80)에 Conv2d(3, 16, kernel_size=5, stride=2, padding=2, bias=True)를 적용할 때 출력 shape와 파라미터 수는?

문제 2

Residual main branch가 (8, 64, 28, 28), skip branch가 (8, 32, 56, 56)입니다. 단순 add가 실패하는 이유와 가장 일반적인 수정은?

문제 3

a.shape=(2,32,40,40), b.shape=(2,16,40,40)일 때 torch.cat([a,b], dim=1)의 출력 shape는? 이어지는 Conv의 in_channels는?

문제 4

AdaptiveAvgPool2d((1,1))이 고정 해상도 flatten+Linear보다 입력 해상도 변경에 강한 이유와 한 가지 손실은?

문제 5

Forward hook을 달았는데 torch.cat 지점이 출력되지 않았습니다. 이유와 두 가지 관찰 방법은?
정답과 해설

정답 1

H_out=floor((64+4-4-1)/2+1)=32, W_out=floor((80+4-4-1)/2+1)=40이므로 출력은 (4,16,32,40)입니다. 파라미터는 16×3×5×5+16=1,216개입니다. Batch size와 공간 크기는 파라미터 수에 들어가지 않습니다.

정답 2

Add는 대응 원소끼리 더해야 하므로 C/H/W가 다르면 residual 계약을 만족하지 않습니다. skip에 Conv2d(32,64,kernel_size=1,stride=2) projection을 두어 (8,64,28,28)로 맞추는 것이 일반적입니다.

정답 3

출력은 (2,48,40,40), 다음 Conv의 in_channels는 48입니다. Channel concat은 채널을 합치고 나머지 축을 유지합니다.

정답 4

Adaptive pooling이 임의 H/W feature map을 고정된 1×1로 바꾸므로 Linear 입력 feature 수가 채널 수 C로 고정됩니다. 손실은 공간 위치 정보가 평균으로 압축되어 작은 국소 신호가 희석될 수 있다는 점입니다.

정답 5

Module forward hook은 nn.Module 호출을 관찰하며 함수형 torch.cat은 module이 아닙니다. Cat(nn.Module) wrapper로 감싸 hook을 달거나, merge 직전에 명시적 shape assertion/log를 둡니다. torch.fx 같은 graph 도구로 함수형 연산을 추적하는 방법도 있습니다.
